## 1. 契约来源与实现顺序

[需求文档](requirements.md)确定业务行为，本文确定公共协议，[后端规范](backend-guidelines.md)与[前端规范](frontend-guidelines.md)引用本文，不重新定义公共格式。

初始 v1.0 沿用 56 项 API、四态任务、幂等恢复、不可变快照和单次外发确认；用户追加服务端快照命名后为 57 项，名称作为独立展示元数据，源码与引用仍不可变。PATCH 名称沿用同源/CSRF 和严格 JSON 校验，不创建任务、不自动重试；相同名称自然幂等，具体字段及最后成功写入语义见 API 清单。页面渲染恢复不自动提交，工程复验见[第四阶段计划](phase-4-plan.md)。

本文的 JSON 与路径是协议约定；工作台及独立任务簿的实现与验收由阶段计划记录，文档示例不能替代实际验证。示例使用虚构标识，不包含密钥或真实项目源码。方法、路径与归属由 [API 分类与清单](api-catalog.md)维护；具体业务字段在所属任务编码前补充接口表，至少说明方法、路径、输入、响应、错误、幂等性、所属需求及验收用例。

开发时先审阅接口表，再实现 Serializer/View 与契约测试，导出并校验 OpenAPI，最后生成前端类型。出现语义偏差先核对需求，不把生成结果自动视为已批准的新行为。

使用 drf-spectacular 生成 Schema；DRF 官方已弃用内置 OpenAPI 生成功能并推荐该替代方案。[DRF Schema 文档](https://www.django-rest-framework.org/api-guide/schemas/)

## 2. 路径与资源

- 工作台业务路径使用 `/api/v1/`，资源使用复数名词，复合词用短横线，采用尾斜杠。`/csrf/` 是基础协议入口，`/analyses/{analysis_id}/graph/` 是单个图表示，作为清单中明确的单数例外。
- JSON 字段使用 `snake_case`；前端传输类型保留相同名称。
- 业务标识以不透明字符串传输，客户端不得从标识格式推断目录、时间或权限。
- 日期时间采用带时区的 ISO 8601，服务端统一输出 UTC 的 `Z` 形式；前端按显示需要转换。
- 未提供、`null` 与空集合含义分别定义；集合为空使用 `[]`，不能随意以 `null` 代替。
- 引用和资源路径使用工作台内相对 URL，不返回宿主绝对路径。输出 URL 不接受用户任意目标地址透传。

| 接口组 | 所属里程碑 | 编码前必须确定的内容 |
| --- | --- | --- |
| 本地 CSRF 与基础访问 | M1 | 令牌获取、同源限制、错误与 Cookie 规则 |
| 项目、导入、快照、受控文件读取 | M2 | 上传格式、资源上限、快照发布、导入摘要和源码分段读取 |
| 任务创建、读取与重试 | M1/M2 | 本文状态、幂等键、超时、结果与失败记录 |
| 接口目录、图、诊断与源码引用 | M2/M3 | 支持矩阵、结果归属、候选关系和覆盖说明 |
| 上下文预览、发送确认、讲解 | M4 | 固定服务配置、预览绑定、模型错误、证据与版本 |
| 知识卡片、练习、作答记录 | M4 | 题目及答案版本、提交格式、历史与反馈 |
| 固定实验及运行记录 | M5 | 允许的输入、固定示例版本、实际观测与数据隔离 |

M1-T03 的示例应用业务 API 与工作台管理 API 是不同服务，其路径相似不表示数据互通。示例三个操作单独生成在 `examples/task-board/contracts/openapi.yaml`，字段和错误遵循本文，具体输入与幂等比较见 API 清单 4.6。示例人工预期按版本、文件摘要与行号绑定，不伪造导入快照；M2 才建立实际 snapshot_id。实验调用只能使用服务端配置的固定目的地。

## 3. 成功响应与分页

成功响应直接返回资源，不外包 `code: 0`、`success: true` 等重复 HTTP 含义的字段。同步创建使用 `201`，普通读取/更新使用 `200`，无正文完成使用 `204`；不要把失败包装成 `200`。

列表采用页码分页：请求参数为 `page` 和 `page_size`，默认 `page=1`、`page_size=20`，最大 `page_size=100`。非法或超界参数返回 `400 VALIDATION_ERROR`，不静默修正；页码超过有效范围返回 `404 PAGE_NOT_FOUND`。空列表第一页返回正常空结果。

列表响应固定为 `count`、`next`、`previous`、`results`，其中翻页链接为同源相对 URL 或 `null`。每个列表必须定义稳定排序并使用唯一标识作为同值时的次序依据。

```json
{
  "count": 1,
  "next": null,
  "previous": null,
  "results": [
    {
      "id": "project_example",
      "name": "内置任务示例"
    }
  ]
}
```

下载文件或受控源码内容需要在具体接口表明确内容类型及读取上限，不套用分页 JSON。所有输出仍受快照与文件清单约束。

## 4. 统一错误

HTTP 错误对象固定包含 `code`、`message`、`details`、`request_id`。

- `code` 为稳定的大写机器码；客户端按代码处理，不解析中文消息判断逻辑。
- `message` 为可理解的简体中文说明，不包含秘密、原始供应商响应、栈或宿主路径。
- `details` 始终为对象，无额外信息时为 `{}`；字段错误统一放在 `details.fields` 下，各字段对应字符串数组。
- `request_id` 为服务端生成的不透明请求标识，同时以 `X-Request-ID` 返回，便于关联脱敏诊断。

```json
{
  "code": "VALIDATION_ERROR",
  "message": "请求参数不符合要求。",
  "details": {
    "fields": {
      "name": ["此字段不能为空。"]
    }
  },
  "request_id": "request_example"
}
```

| HTTP 状态 | 典型代码 | 语义 |
| --- | --- | --- |
| 400 | VALIDATION_ERROR、INVALID_ARCHIVE | 输入或归档不符合规则 |
| 403 | CSRF_REJECTED、ORIGIN_REJECTED | 本地浏览器写操作保护失败 |
| 404 | RESOURCE_NOT_FOUND、PAGE_NOT_FOUND | 资源或页码不存在 |
| 409 | IDEMPOTENCY_CONFLICT、SNAPSHOT_NOT_READY、CONSENT_STALE、MODEL_NOT_CONFIGURED | 当前状态无法执行或请求约定冲突 |
| 405 | METHOD_NOT_ALLOWED | 已有资源不支持该方法；写方法仍校验来源与 CSRF |
| 406 | NOT_ACCEPTABLE | Accept 不允许服务提供的 JSON 响应 |
| 413 | REQUEST_TOO_LARGE、ARCHIVE_LIMIT_EXCEEDED | 基础 JSON 正文或上传/展开资源超过限制 |
| 415 | UNSUPPORTED_MEDIA_TYPE | 不支持的请求内容类型 |
| 500 | INTERNAL_ERROR | 未预期服务端失败，详细诊断仅在脱敏服务端记录 |
| 503 | SERVICE_UNAVAILABLE | 依赖不可用且请求尚未被可靠接收 |

任务执行中的解析、模型与实验错误写入任务的 `error`，错误代码按所属任务接口表补充；不是把后续 `GET` 任务查询一律改成 `5xx`。成功读取一个已失败任务仍返回 `200`。

工作台内部可控制的错误处理边界应遵循上述对象，包括上传限制与 CSRF 拒绝。代理、浏览器网络失败等无法取得合法 JSON 的情况由前端统一转换为传输错误，不能伪造服务端 `request_id`。

## 5. 长任务、幂等与重试

### 5.1 创建与读取

耗时操作可靠接收后返回 `202`、任务资源及同源 `Location`。先完成必要请求校验，不能以任务形式掩盖确定的非法参数。任务持久化和队列发布的恢复方式见[后端规范](backend-guidelines.md)。

任务公共字段为：`id`、`kind`、`snapshot_id`、`status`、`stage`、`progress`、`previous_job_id`、`result_url`、`error`、`created_at`、`updated_at`。

- `snapshot_id`：分析和讲解任务必须绑定快照；导入任务在发布成功前可为 `null`，发布后关联新快照；固定实验通过其结果标注示例版本，不冒充导入快照运行。
- `stage`：当前可解释的阶段标识，由具体任务定义，不代替 `status`。
- `progress`：仅记录真实处理量，如 `processed` 和可为空的 `total`；无法计算时为 `null`。
- `previous_job_id`：显式重试时指向前一次任务，否则为 `null`。
- `result_url`：成功后指向持久化结果，否则为 `null`。
- `error`：失败时使用统一错误对象，否则为 `null`；任务内部错误使用其失败记录的请求/诊断标识。

```json
{
  "id": "job_example",
  "kind": "analysis",
  "snapshot_id": "snapshot_example",
  "status": "queued",
  "stage": "queued",
  "progress": null,
  "previous_job_id": null,
  "result_url": null,
  "error": null,
  "created_at": "2026-09-28T00:00:00Z",
  "updated_at": "2026-09-28T00:00:00Z"
}
```

### 5.2 状态转换

| 当前状态 | 允许的后续状态 | 条件 |
| --- | --- | --- |
| queued | running | Worker 成功取得有效执行资格 |
| queued | failed | 投递失败或超过排队期限等，记录明确原因 |
| running | succeeded | 结果已经持久化并可读取 |
| running | failed | 执行错误、期限失效或 Worker 失联，经核对后终结 |
| succeeded | 无 | 终态不可回退 |
| failed | 无 | 终态不可回退；显式重试另建任务 |

任务成功表示执行完成并生成有效结果，部分解析可作为成功结果，但必须携带覆盖说明和诊断。首版不增加 `partial`、`unknown` 或 `cancelled` 任务状态；运行不确定性放入诊断和期限核对处理，不虚报成功。

### 5.3 幂等规则

- 首版 API 清单中的所有业务 POST 使用 `Idempotency-Key`，包含同步创建和异步提交。键为客户端生成的随机、不含敏感内容的操作标识，不具有认证作用。
- 服务端在动作与目标资源范围内保存键、请求摘要及所关联资源或任务，并通过数据库唯一性保证并发提交的一致性。
- 首次同步创建返回 `201` 和资源；首次异步提交可靠接收返回 `202` 和任务。同一键与相同请求摘要返回原资源或任务及 `200`，不再次执行。接口的成功模式见 [API 清单](api-catalog.md)。
- 相同键对应不同输入、快照、模型确认或实验配置时返回 `409 IDEMPOTENCY_CONFLICT`。
- 客户端超时但不确定是否接收时，使用原键和相同载荷恢复；不能自动换键重发。
- 已失败任务的显式重试使用新键、创建新任务并设置 `previous_job_id`；不能把失败任务原地改回排队。
- v0.1 幂等记录随对应资源或任务保留，不做隐式短期过期。新导入是新的用户操作，新键生成独立快照。

M2-T04 已实现三类现有任务的显式重试，输入与错误见 [API 清单 4.11](api-catalog.md)。导入重传原 ZIP 并核对原摘要；分析复用原快照和入口；失败记录不原地恢复。前端必须接受可空 UUID previous_job_id。投递异常并不证明消息未被接收，返回任务 Location 后应读取持久化状态；已领取或完成的任务不被投递异常回退。

工作台不自动重试潜在计费模型请求。模型超时后的人工重试需提示供应商可能仍已处理上次请求，不能承诺停止计费。任务失败不会自动删除已发布的旧快照或历史记录。

## 6. 快照、引用与证据语义

所有解析节点、边和源码引用均指向明确快照；不能用相同路径在“最新快照”中自动替换原引用。

源码引用公共字段为 `snapshot_id`、`file_path`、`start_line`、`end_line`。路径是清单中的相对路径，统一使用 `/`；行号从 1 开始，首尾均包含，必须满足 `1 <= start_line <= end_line` 且位于文件范围内。

```json
{
  "snapshot_id": "snapshot_example",
  "file_path": "backend/tasks/serializers.py",
  "start_line": 12,
  "end_line": 18
}
```

来源语义区分源码事实、静态推断、通用原理和内置实验观测。具体 DTO 在 M2/M4/M5 细化，但禁止将这些来源压成一个无说明的“已验证”标记。

静态结果附规则版本、覆盖摘要与诊断；模型讲解附模型标识、模板版本和证据；实验附固定示例版本、运行标识、输入和实际观测。不存在适用来源时明确缺失，不生成假引用。

M2-T02 的具体 DTO 见 API 清单 4.9。`source_fact` 的引用对应实际 AST 位置；`static_inference` 标记固定属性关联；`framework_rule` 使用规则标识并允许 source_ref=null，不能把框架默认方法伪装为用户方法。源码引用始终使用本次快照和清单路径。分页条目属于 URL 中的固定 analysis_id。

M2-T03 图 DTO 见 API 清单 4.10。图作为一个有界表示返回，节点/边绑定父分析的快照、解析版本和独立图版本；查询根标识只能属于该图。解析覆盖、关系缺口和查询截断分别表达，不能压成“完整”标记。节点共享不代表动态调用成立，重复接口候选保持独立。历史无图返回 409 GRAPH_NOT_AVAILABLE，不在 GET 中回填；新操作键分析原快照可生成新结果，旧结果不变。M2-T03 当时没有前后端关联；M3 已增加前端节点和关联，见下文 M3 扩展与 API 清单 4.12。当前仍没有单独节点/边资源 API。

## 7. 外发确认与模型协议

上下文预览接口仅准备可审阅片段，不调用外部模型。用户确认后，服务端核对快照、片段内容、目标服务、模型与提示模板版本，保证真正发送的内容处于确认范围。

确认凭据由服务端维护并与预览绑定；客户端只传递相应标识，不能自行声明任意内容已获确认。确认范围变化返回 `409 CONSENT_STALE`，不得自动扩展授权范围。

浏览器看见经脱敏的服务显示信息和模型，不接收密钥或带凭据的 URL。密钥只由本地服务端配置注入；正常分析请求不能更改模型地址。

Chat Completions 兼容性测试包括基础消息、非流式文本返回、鉴权失败、超时、空内容、异常结构与可选用量字段。应用自身的结构化讲解校验独立于供应商是否支持特殊输出模式。

首版不把模型返回的工具调用作为指令执行。具体服务只有通过兼容性用例才可标记“已验证”，改变模型或服务地址后原标记不自动沿用。

## 8. 本地单用户访问边界

- 对宿主发布的入口仅绑定回环地址。容器内部监听规则与宿主端口发布分开验证，内部数据库、Redis、实验服务不直接对外发布。
- 前端通过同源代理访问 API；明确选定入口的协议、主机和端口，不将任意 `localhost` 端口视为同源，不使用通配 CORS。
- 校验 Host，写操作校验 Origin 与 CSRF。缺少合法来源信息的写操作拒绝；固定代理后的来源按受信任代理配置还原，不能信任任意客户端转发头。
- 首版不设注册和登录流程。匿名本地请求也必须实施写操作 CSRF，不能依赖只对已认证请求生效的 SessionAuthentication 行为。[DRF SessionAuthentication](https://www.django-rest-framework.org/api-guide/authentication/#sessionauthentication)
- `GET /api/v1/csrf/` 获取 Django 标准 CSRF 令牌并设置对应 Cookie，JSON 字段为 `csrf_token`，响应禁止缓存。统一客户端在后续写请求中通过 `X-CSRFToken` 发送，令牌不写日志。
- 使用 Django 标准 CSRF 生成与验证机制，不自制密码学协议；具体中间件/装饰器组合通过 AT-24 验证匿名请求确实受保护。[Django CSRF 文档](https://docs.djangoproject.com/en/5.2/ref/csrf/)
- Cookie 使用 host-only 范围和明确 SameSite 策略；HTTPS 环境开启 Secure。本地 HTTP 开发配置不能被描述为适合公网部署。

这套边界针对本机可信单用户，不防御同一操作系统下的恶意本地进程，也不构成公网身份认证。若要允许局域网、公网或多用户访问，必须先进入路线图中的独立安全设计。

## 9. 契约验证与变更

每个具体接口编码前填写接口表，关联 FR/NFR 和 AT，并覆盖正常、非法、资源不存在、状态冲突、依赖失败及重复请求。文件上传、任务轮询和外发确认的错误也必须有 Schema。

实现后从 `backend` 将 OpenAPI 导出到 `../contracts/openapi.yaml`，核对相对设计约定的变化；再从 `frontend` 读取该文件，生成 `src/shared/api/generated/schema.d.ts`。两套服务的生成与漂移检查命令已建立，实际验证见阶段计划；未实现端点不进入生成产物。`operation_id` 使用稳定业务动作名称，如 `projects_list`、`analyses_create`，不能随 View 重命名而改变。生成文件标明来源并禁止手改，Schema 能解析不代表业务语义已验证。

字段删除、语义变化、状态枚举或错误代码变化属于契约变化，需要同步前后端和相关用例。首版通过同一版本协同修改；有外部消费者后再单独定义兼容与迁移政策，不能预设所有调用方都会同时升级。

两端类型生成器提供 `npm run api:types:check`，只比较重新生成的声明，不覆盖现有文件；缺失、漂移或生成失败非零退出。根目录 `scripts/check_contracts.py` 使用执行它的 Python 和 `--node` 指定的 Node，顺序导出到临时目录、核对保存的 OpenAPI 与 API 清单 4.7/4.8/4.9、执行无数据库契约测试、检查生成类型及 TypeScript。检查不安装依赖、不启动服务、不读取实际秘密或连接数据库；产物与实现不一致时先审阅再显式生成。响应体测试使用锁中已有的 jsonschema 校验转换后的 OpenAPI 3.0 nullable 结构，并另行核对状态、请求标识和错误语义；数据库响应由 PostgreSQL 用例验证。

前端 `ApiError` 保留经过运行时校验的 `code`、`details` 和 `requestId`，引用生成 Error 类型；畸形 JSON 错误、HTML 和网络异常不伪造这些字段。写请求继续不自动重发，任务失败正文的请求标识不被当前读取请求覆盖。

运行测试结果在[开发计划](phase-1-plan.md)按任务记录。M1-T02 已建立真实基础端点、有限 Schema 和生成类型，验收证据见阶段计划。固定链路检查不绑定导入快照，结果明确使用 check_version；不生成源码证据或模型观测。

### M3 扩展与兼容约定

M3 完成时 HTTP 操作数量为 19；M4 增至 32。分析提交保持仅 root_urlconf；详情新增可空 frontend，null 专指旧记录未分析前端，不等于新结果的零前端文件/请求。前端协议 typescript-analysis/1.0.0、解析规则 typescript-react/1.0.0、关联规则 method-path/1.0.0 独立表达来源。图 v2 与旧 v1 都可读取，GET 不回填历史。

接口 index 是原结果内固定零基序号；frontend_links 指向图请求 UUID，并携带状态、原因和引用。图 endpoint_index 与 root_node_id 互斥，前者读取接口上游前端及下游后端，后者继续仅沿出边。确认与候选使用独立边类型；源码包含不能称为执行路径。查询预算、截断、快照归属与来源校验仍生效。

任务列表可带 kind、snapshot_id，并在分页链接保留过滤条件；缺省查询兼容旧行为。请求路径仅保留关联所需路径部分，不保存查询串、片段、请求头或请求体。原始路径与基础路径变换的证据由源码引用和规则表达；不把未知配置静默补为同源。完整字段与失败映射见 [API 清单 4.12](api-catalog.md#412-m3-前后端关联契约)。

### M4 确认、结果与作答约定

预览、确认、提交是三个独立 POST。预览存储精确两条消息、配置/模板版本、片段及摘要；GET 和确认均无外发。服务端确认在创建 ExplanationRequest 与 Job 的同一事务中单次消费，行锁与唯一约束共同保证并发幂等。旧键恢复先返回原任务，不因后续配置变化重新调用；新操作不能重复消费旧确认。实际发送前再次检查配置、快照和执行资格，终态或过期领取不能发布结果。

讲解重试在 API-17 使用新 consent_id，必须属于原预览；更换配置或内容则新建预览与讲解操作。模型未配置/失效时 GET 历史与学习接口继续可用。浏览器按明确未受理的机器码清理操作键，网络未知、幂等冲突与投递未知不能自动换键。

新预览 configuration 仅含 `base_url` 和 `model`。请求不发送输出限额参数，不设应用输入/响应字节预算或请求总期限；合法 `usage` 仅记录非负整数用量，不作为拒绝阈值，缺失保持 null。供应商限制及账单由用户判断，拒答、截断、非法响应及无效引用仍拒绝发布。

ModelTarget 的历史 `timeout`、`context_bytes`、`output_tokens`、`token_field` 改为可选，只用于读取旧预览；旧配置绑定与新配置不同，旧确认返回 CONSENT_STALE，必须新建预览和讲解操作。HTTP 路径、状态和数据库结构不变，旧结果不回填。模型等待期间续期 Job 领取；活跃请求无固定总期限，失效领取和终态仍拒绝迟到结果，不自动重发。

标准答案仅存在后端内容和作答反馈；题目 GET 不返回答案。作答追加保存，不覆盖旧记录；输入快照和分析必须匹配，版本不匹配返回 EXERCISE_VERSION_MISMATCH。内容加载是显式、事务性、同版本不可覆盖的维护动作，没有题目编辑 API。维护者身份与未独立审阅边界随题目/卡片返回。

### M5 实验的上下文、幂等与事实来源

工作台新增五个操作，总数 37。实验 Job.snapshot_id 为 null，LabRun.snapshot_id 通过绑定分析表达学习上下文；实际运行来源是独立固定示例及其版本，不能宣称执行了该快照。提交保存预测与定义副本，后续 GET 不重新解释历史。

公开提交使用 UUID Idempotency-Key 与完整请求摘要，同键同请求先恢复旧任务，冲突载荷拒绝；失败重试以新键创建新运行并关联原任务。内部固定资源使用 run_id/case 派生写入键，重复请求不重复插入。关闭保留标记且与写入共享行锁，不能通过重复 open 延长期限或复活已关闭运行。

观测来自独立服务真实 HTTP 与 scoped 数据计数，先保存响应再验证；响应不完整时，后计数为空且任务失败。预测、静态推断与观测分别显示。无法确认关闭时记录 unconfirmed；以后到期回收不静默改写当时的证据。具体输入、响应字段、错误和内部身份例外见 API 清单 4.13。

### v0.2 分析增强契约

本节记录分析增强契约。API-38 至 API-46、snapshot_comparison 任务类型及附加人工元数据均已从实现导出，字段和错误见 API 清单 4.14–4.16。接口编号与路径见 [API 登记清单](api-catalog.md#v02-api-plan)，M6–M10 状态与执行记录仅见[第二阶段计划](phase-2-plan.md)。产品 v0.2 保持 HTTP `/api/v1/`。

- 人工决定独立于不可变分析追加保存，归属精确到分析、请求与候选目标，记录时间和修订；同请求最多一个人工确认。期望修订冲突使用 409，不能静默覆盖；同键同输入先恢复原记录，不因后续修订重复执行。撤销保留历史。新增人工元数据不得改写原始静态状态或伪装为 source_fact，也不进入模型消息或改变外发确认范围。
- 对比绑定同项目的两个显式快照，接口/关系对比另需成对分析；不以最新记录隐式替换绑定。分析 UUID、图 UUID 或单纯行号偏移不能作为跨快照的语义身份。规则版本或入口不同、接口重复、节点模糊均明确不可直接比较或待判断，不伪造增删结论。
- `snapshot_comparison` 沿用四态及执行资格，Job.snapshot_id 为目标快照，业务请求保存双侧完整绑定；重试创建新尝试，不覆盖历史。服务端/客户端运行时校验、Schema、筛选及重试契约同步该类型。完整对比结果与任务成功原子发布；失败/超限不发布半成品，GET 不解析或回填。
- 证据适用性以目标快照为参照，区分引用文件未变、需要复核、来源已删除和无法判断；它不是原快照引用的全局失效标记，更不等于讲解语义正确性。原引用仍读旧内容，旧讲解、预览和确认不改写，不自动发起模型调用。
- 影响结果绑定各侧分析/图和人工决定修订。默认不使用未决候选，开启后标注依赖候选的范围，人工排除始终优先。路径、覆盖缺口和查询截断分别表达，空结果不能宣称无影响。
- 新操作继承来源/CSRF、严格输入、统一错误、幂等与有界分页。增量迁移保留旧记录和图 v1/v2 读取，未实现操作不得进入当前 OpenAPI 或类型产物。

### v0.3 学习增强契约

API-47 至 API-56 沿用 `/api/v1/`、Origin/CSRF、严格查询、分页、统一错误和幂等；字段及稳定 operation_id 见 API 清单 4.17，验收只见[第三阶段计划](phase-3-plan.md)。

- 自评记录包含 attempt_id、judgement 和不超过 1000 字的 note，只追加用户判断；正确性和 hint_used 仍来自原作答。重新作答使用 previous_attempt_id 关联同题版本、快照、分析和接口；可省略或 null，两种旧式输入摘要等价。跨归属返回 409 REATTEMPT_SCOPE_MISMATCH。

- observed 表示实际获取观测，不能与预测一致性混淆；unavailable/invalid、部分观测和 cleanup pending/completed/unconfirmed 分别表达。超时场景真实终止且回收属于正常实验结果，清理不确认不能成功发布。失效领取不能写迟到观测。
