# v1.0 小范围试用协议与观察模板

本文件负责试用步骤与记录格式，不维护开发任务状态。实际参与、发现、处理结论仅汇总至[第四阶段计划](phase-4-plan.md)。当前没有真实参与者或反馈，本模板为空；工程验收不能替代试用。

## 1. 范围与准备

建议 2–5 位有基础代码阅读能力、使用过编码辅助工具但难以解释功能链路的参与者；样本量是计划，不是已有人数。不主动发送邀请，参与和沟通由用户安排。

只使用本项目受控任务簿，或另经所有者授权且确认无敏感内容的小型 DRF + React 项目。开始前说明源码只读、实验只作用受控示例、数据保存在本机；本轮模型保持关闭。如确需模型，独立审阅目标/片段并单次确认，不能从试用同意推导无限调用权限。

主持人先按[演示文档](v1-demo.md)启动隔离 5181 实例，确认标准数据可用。参与者记录用匿名编号 P01/P02，不收集姓名、账号、公司、原项目源码、录音或凭据。反馈只记录非敏感操作与理解障碍；不要粘贴含秘密的命令、配置或原始响应。

## 2. 两项近似难度任务

每个任务均包含代码定位、结果预测与过程解释三问，围绕同一接口与校验链路，限时各 5 分钟；允许未完成。无需编写或执行任意项目代码。

| 任务 | 代码定位 | 预测 | 过程解释 |
| --- | --- | --- | --- |
| A：缺少 title 的创建请求 | 找到请求入口、TaskSerializer 的字段校验与创建位置，指出源码行 | 预测 HTTP 状态和新增任务数 | 解释失败发生在何处、为何未写入以及前端如何显示错误 |
| B：title 为纯空白的创建请求 | 找到同一链路中规范化与校验相关源码，指出源码行 | 预测 HTTP 状态和新增任务数 | 解释空白处理、失败与数据库写入的先后及前端反馈 |

两项参考结果均为 400、写入 0 条，答案核对依据现有样例、独立人工基准及真实请求实验；不是模型评分。主持人在参与者独立作答后才核对答案，避免提前给出提示。

部分参与者先 A 后 B，其他人先 B 后 A，记录顺序。先做第一项取得个体基线，再用工作台浏览源码/路径、练习和实验 8–10 分钟，最后独立完成另一项。两任务仍可能有迁移、练习与顺序效应；有限样本只报告个体变化，不作因果或普遍教育效果结论。

## 3. 观察与求助

主持人不替参与者点击或回答。卡住时先记录位置和时长，再按顺序给予一级定位提示、二级操作提示、三级答案提示；使用哪一级就如实记录。无提示完成、提示后完成、未完成分别表达，不把提示后正确当作独立掌握。

记录错误理解时引用简短的非敏感表述，区分“找不到入口”“不理解关系类型”“把静态候选当作运行结果”“不知道失败是否已提交”和“把自评当作掌握度”。如出现秘密或错误外发迹象，停止该操作并处理实际问题；不保存敏感原文。

## 4. 空白记录模板

复制下表填写实际信息，保留空白表示未观察，不填造时长或结论。不要将观察模板的存在写成“试用通过”。记录存放在用户控制的本地非敏感位置，汇总时只保留可复用结论。

| 字段 | 实际记录 |
| --- | --- |
| 匿名编号 / 日期 / 产品与样例版本 | 待填写 |
| 参考设备与窗口大小 / 模型是否关闭 | 待填写 |
| 顺序（A→B 或 B→A） | 待填写 |
| 第一项：定位 / 预测 / 解释 / 用时 / 提示级别 | 待填写 |
| 工作台：求助位置 / 错误理解 / 交互障碍 | 待填写 |
| 第二项：定位 / 预测 / 解释 / 用时 / 提示级别 | 待填写 |
| 刷新与历史：是否能恢复原对象和提交结果 | 待填写 |
| 未覆盖写法 / 未完成原因 | 待填写 |
| 个体观察与不确定性 | 待填写 |
| 问题严重性 / 复现步骤 / 处理结论 | 待填写 |

## 5. 问题处理与退出条件

阻断核心操作、数据归属错误、重复提交、错误外发和清理无法确认优先处理；展示不清晰、难找入口、键盘问题其次。仅可在当前授权范围修复，其他候选功能另行决策。每个问题有复现或无法复现结论、测试证据和限制，不用“已优化”代替可核对事实。

真实试用退出需要实际参与记录、关键障碍与错误理解的结论，以及必要修复的验证。若没有参与者，工程开发和材料可交付，M20-T02 保持待执行，产品适用性及教育效果不扩大宣称。开发与验收证据只在第四阶段计划维护。
