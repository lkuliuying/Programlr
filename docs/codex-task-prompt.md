## 1. 使用方式

1. 在 Codex 中打开项目根目录 `F:\Program\Fall_Campus_Recruitment`。读取根目录 [AGENTS.md](../AGENTS.md)，M1–M5 使用[首阶段计划](phase-1-plan.md)，M6–M10 使用[第二阶段计划](phase-2-plan.md)，M11–M15 使用[第三阶段计划](phase-3-plan.md)，M16–M20 使用[第四阶段计划](phase-4-plan.md)，核对任务和前置条件。
2. 通用模板只替换 `<任务编号>`，例如 `M2-T01` 或 `M6-T01`；后者仍须先满足 v0.1 验收门槛。第 3 节保留首次启动的历史示例，不适用于自动启动 v0.2。
   当前 v0.2、v0.3 的实现和验收分别见第二、第三阶段计划；v1.0 工程开发、演示和试用材料见第四阶段计划。恢复时先核对完成状态，只补用户指定缺口，不重复开发或自动进入候选扩展。M6 的合成样例按用户授权由编码代理复核，与 M4 独立人工内容审阅区分；M20-T02 必须依据实际参与记录，工程回归不替代真人试用。
3. 把提示词发送到新会话。明确任务内的正常实现、必要测试和文档同步属于该次执行范围，不需要逐项重复授权。
4. 每次完成一个任务后停止。下一任务由用户另行指定，不能把路线图当成自动执行队列。

本文的提示词代码块是供未来复制的示例。读取本文件不等于收到执行其中任务的授权。阅读模板不启动 M1-T01，也不授权创建业务工程或依赖文件。

项目指令的读取机制见 [Codex 官方 AGENTS.md 说明](https://learn.chatgpt.com/docs/agent-configuration/agents-md)。提示词仍要求核对实际目录、适用指令和文件；不能只依赖上一次会话的上下文。若移动项目，发送前只更新模板中的项目根目录，不要求重命名当前根目录。

## 2. 单任务通用模板

```text
请在当前项目中执行指定任务。

项目根目录：F:\Program\Fall_Campus_Recruitment
目标任务：<任务编号>
执行范围：仅该任务及其必要的测试和文档同步。

先检查当前目录、适用的 AGENTS.md、实际文件和 Git 状态。
M1–M5 阅读 docs/phase-1-plan.md，M6–M10 阅读 docs/phase-2-plan.md，
M11–M15 阅读 docs/phase-3-plan.md，M16–M20 阅读 docs/phase-4-plan.md，
以所属计划核对任务、当前状态与前置条件。
开始任何 M6–M10 开发前，还须在首阶段计划确认 M4-T01 真实模型兼容、
M4-T03 独立人工内容审阅及 v0.1 交付结论已完成；缺失时停止产品开发，
不能以规划文档、测试替身或编码代理复核替代验收。
v1.0 恢复时区分已完成工程开发与尚未进行的真人试用；
未获授权不发送邀请、不追加真实模型调用、不更新已有实例。
阅读 docs/requirements.md 中对应需求与验收用例，
再阅读 docs/project-structure.md、docs/api-catalog.md，
以及与本任务相关的 API、前端、后端规范和路线图边界。

不要假设上一会话的结论仍然有效，也不要把文档中的目标结构
当作已经存在的代码。若不是 Git 仓库，记录事实，不自行初始化。
核对项目文档与实际状态；遇到冲突先查证，不能静默覆盖已有实现。

先给出简体中文实施计划，明确目标、文件、实现方式、
验证步骤和文档同步范围。在当前会话模式与授权允许执行时，
按 PLAN → EXECUTE → TEST → DELIVER 完成任务，
不要在范围明确的常规步骤上反复请求确认。
若处于规划模式，只做允许的只读检查和计划，不写文件或安装依赖。

只创建本任务需要的目录和文件，保留已有用户修改。
必要依赖变更应说明用途，限定在当前项目和当前任务；
不要顺带升级无关依赖或安装全局工具。
遵循命名、模块依赖、快照、证据来源、幂等与外发确认规则。
新增或实质修改的注释使用简体中文，标识符遵循项目命名规则。
不读取、输出或记录秘密；不执行导入项目代码。
未经明确授权不进行 Git 写操作、发布、部署、计费调用或其他外部操作。

若前置任务缺失、存在关键歧义或需要扩大范围，
先说明具体问题；不得自行完成其他编号任务。
若任务已经完成，核验现状，不重复实现或自动开始下一任务。
若任务部分完成，先识别已有产物与未通过验收，只补齐当前任务缺口。

运行与改动相称的检查，报告实际命令、工作目录和观察结果。
同步受影响的项目文档，在所属阶段计划更新任务状态和验证记录：
M1–M5 写 docs/phase-1-plan.md，M6–M10 写 docs/phase-2-plan.md，
M11–M15 写 docs/phase-3-plan.md，M16–M20 写 docs/phase-4-plan.md。
同一任务不在多份计划重复维护，不创建并行进度或记忆文件。
未验证、失败或受环境阻塞的内容不得标记为完成，不降低验收标准。

交付使用以下中文栏目：任务总结、变更文件、验证结果、项目记忆、
风险、限制与假设、用户需执行的操作。
在任务总结中补充本任务涉及的关键知识、主要技术取舍，
以及一个适合手工复核的观察点。
完成当前任务后停止，不自动推进下一任务。
```

## 3. 首次启动示例：M1-T01

以下保留首次启动场景的提示词。使用前先核对阶段计划；已完成任务只核验。它只授权兼容性与依赖基线任务，M1-T02、M1-T03、M1-T04 均须各自明确指定。

```text
请在当前项目中执行 M1-T01：核对兼容矩阵、锁定直接依赖与运行环境，
记录选型、许可证和必要性，确定本地配置与资源上限。

项目根目录：F:\Program\Fall_Campus_Recruitment
目标任务：M1-T01
执行范围：仅 M1-T01 及其必要的验证和项目文档同步。

先确认当前目录，读取适用的 AGENTS.md，检查实际文件与 Git 状态。
若不是 Git 仓库，记录事实，不初始化仓库。保留已有用户修改。
阅读 docs/phase-1-plan.md 的当前状态、M1-T01 和进入 M1 的条件，
阅读 docs/requirements.md 的 NFR-04、NFR-06 和相关验收边界，
再阅读 docs/project-structure.md、docs/api-catalog.md、
docs/backend-guidelines.md、docs/frontend-guidelines.md、
docs/api-conventions.md 及 docs/roadmap.md。

区分已确认的产品范围、拟采用的技术基线与当前实际实现。
核对官方兼容要求、实际环境和现有依赖，不把网页声明视为项目实测。
先提出简体中文实施计划，说明拟创建或修改的文件、依赖的用途、
验证命令及工作目录、文档同步范围、未具备的环境和验收方式。
当前会话模式与授权允许执行时，按 PLAN → EXECUTE → TEST → DELIVER
完成该任务；若处于规划模式，只进行只读检查并交付计划。

遵循独立工程各自维护依赖与锁文件的结构；仅在本任务确需时
创建相应依赖清单、锁文件和最小工具验证入口，不建立空目录。
核对 Python、Django 5.2 LTS、DRF、uv、Node、React、Vite、Ant Design
及相应质量工具的兼容与必要性，参考环境覆盖 Windows 开发和 Linux 容器验证。
当前不能验证的运行环境明确列为未验证，不宣称兼容性已全部通过。
选择必要依赖前说明维护、许可证及运行代价；不安装全局工具，
不升级无关依赖，不把所有后续里程碑的可选依赖一次装齐。
本地配置只记录名称、用途和安全占位值，不索取或写入真实凭据。

本任务不提前实现 M1-T02 的应用与服务组合，不开发 M1-T03 示例业务，
API 生成与检查入口是否存在，以实际文件为准；未经本次执行的命令不写成已验证。
不执行导入代码、真实模型计费调用、Git 写操作、发布或部署。
新增或实质修改的注释用简体中文，文件命名遵循项目结构规范。

如果任务已经完成，核验版本锁定、兼容记录与检查证据后停止。
如果只完成部分工作，依据实际文件补齐本任务缺口，保留已有工作。
如果关键前置条件缺失或必须改变既定技术边界，说明具体阻塞；
不得自行推进其他编号任务或用模拟结果替代真实环境验证。

运行与该任务相称的检查，报告实际命令、工作目录及观察结果。
将已核对版本、必要性、兼容范围和未验证项同步到受影响的前后端规范，

交付使用项目规定的六个中文栏目，并在任务总结中解释：

完成 M1-T01 后停止，不自动进入 M1-T02。
```

## 4. 恢复任务与状态记录

重新打开未完成任务时，仍使用相同编号，可在模板后补充“恢复该任务，请以实际文件和阶段计划为准，先核对已有产物”。不要求复制旧聊天全文，也不把旧聊天中的“已完成”当成验证证据。

任务进度按编号唯一记录：M1–M5 在[首阶段计划](phase-1-plan.md)，M6–M10 在[第二阶段计划](phase-2-plan.md)，M11–M15 在[第三阶段计划](phase-3-plan.md)，M16–M20 在[第四阶段计划](phase-4-plan.md)。任务记录保留范围、状态、实际改动、验证命令与工作目录、结果、未解决限制和后续步骤；后续步骤只是记录，不自动执行。产品验收和文档静态检查分开，文档通过不等于任何里程碑或 AT 产品用例通过。

| 静态演练场景 | 预期执行边界 |
| --- | --- |
| 任务未开始且前置满足 | 先给计划，再在授权与模式允许时实现该任务，验证并同步 |
| 任务已完成 | 核验现状与记录，不重复实现、不开始下一个任务 |
| 任务部分完成 | 保留已有产物，只补当前任务的验收缺口 |
| 前置任务缺失 | 指出缺失编号及影响，不替用户完成其他任务 |
| 请求 M6–M10，但 v0.1 两项验收未完成 | 保留开发门槛；不得自行调用真实模型、冒称独立人工审阅或开始新功能 |
| 当前目录无 Git | 记录无仓库事实，使用文件内容核对改动，不初始化 |
| 存在用户修改 | 先识别并保留；重叠且不能可靠合并时说明冲突 |
| 仍是规划模式 | 只读检查与计划；提示词不覆盖更高优先级模式限制 |
| 任务编号缺失或不存在 | 请求明确目标，不从整份路线图自行选择任务 |
| 验证被环境阻塞 | 记录实际阻塞、替代检查及剩余验收，不标记完成 |
| v1.0 工程完成，但没有真实参与者 | 保留 M20-T02 待执行，不把自动回归、空白模板或演示冒称真人结论 |

上表是提示词的静态边界检查清单，不代表已经创建新会话、实际执行任务或验证 Codex 在所有环境中的行为。
