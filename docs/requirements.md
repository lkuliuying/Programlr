## M27 当前产品范围

M27 延续 M26 的三入口和退役边界；本节为当前规则，M1–M26 的界面与验收保留为阶段历史。课程、练习、实验、比较、影响、人工校准、通知写入及基础检查仍退役，旧写入口返回 `410 FEATURE_RETIRED`。本轮进度和实际证据唯一见[第四阶段计划 M27](phase-4-plan.md#m27)。

当前主流程为：导入 ZIP／文件夹 → 持久化扫描源码 → 唯一根路由自动分析（多根才选择）→ 联动阅读源码、接口、关系和知识 → 按需预览、确认并生成模型讲解。三个主入口是项目管理、统一项目工作区、操作日志。

### M27 界面与读取验收要求

- 三张用户参考图定义项目管理、只读工作区、日志的构图；使用真实摘要与统计，不复制示例数字、账号或500MB文案。ZIP20MiB/目录100MiB等原限额继续有效。
- 固定浅色并彻底移除主题切换和内容分页；旧深色偏好、系统深色、存储不可用均不闪黑。Portal、错误页、源码和图在同一浅色体系。
- 项目筛选先于数据分页，最新可读快照被删除时摘要回退；单根、多根、无根、失败与删除恢复保持。活动使用真实事件，不推算进度百分比。
- 标签关闭/去重、主副URL恢复、跨快照隔离、200行跨块/末行跳转、取消迟到读取、1000行渲染上限及草稿保留可验证；相关依据只含已有静态事实。
- 日志统计按操作记录计数，不受当前页/结果页签影响；连续7天/前7天使用服务端同一时刻与可靠结束时间，零分母为空。CSV筛选一致、UTF-8 BOM、公式防护，10000条和10MiB硬上限不得静默截断；关联按身份而非名称。
- 1680×945、1440×900、1280×720、768×1024、390×844及矮窗口检查末条记录、末行代码、对话框末按钮可访问，无页面横向溢出。实际执行结果仅见M27记录，要求本身不是验收证据。

## 2. 产品定位

### 2.1 用户与问题

目标用户能够借助 Agent 生成项目，但难以解释功能涉及的组件、数据流和底层机制，也难以判断模型讲解是否符合实际代码。用户具有基本代码阅读能力，不要求能够独立设计完整应用。

当前项目同时服务于作者的学习与求职展示：通过实现和验证代码分析、Web API、交互界面与受控实验，复习 Python、DRF、React、Docker、计算机网络、操作系统和图算法。

### 2.2 产品目标

- 实现层：用户能够找到功能涉及的文件、组件、接口和数据模型。
- 原理层：用户能够解释数据如何流动、参数在哪里校验，以及常见失败为何发生。
- 验证层：用户能够先预测结果，再通过代码证据、测试或内置实验核对判断。

阅读时长、点击次数和练习完成率只作为辅助指标。首版通过人工核对的练习与实际操作验证功能可用；是否提高学习效果，需要后续真实试用，不能从界面上线或模型评分推断。

### 2.3 运行与信任边界

- 本地单用户、中文界面，面向小型 DRF + React 项目；后端及 Worker 以 Linux 容器为统一验证环境。
- 工作台只读取导入源码，不安装其依赖、不导入其 Python 模块、不执行脚本、不运行其 Docker 配置。
- 不运行导入项目；历史实验结果只读保留，固定实验写入口已退役。
- 模型服务是外部数据接收方；发送前必须告知目标、模型及具体代码片段范围并取得确认。
- 首版不实现账户注册或多用户权限系统。本地访问边界、同源策略与写操作 CSRF 保护仍是必要要求，具体规则见 [API 契约规范](api-conventions.md#local-boundary)。

## 3. 首版范围

### 3.1 主流程

导入项目 → 自动识别根路由与知识 → 查看接口、源码和有依据的关系 → 按需生成讲解。删除和失败操作从操作日志追溯。

首个完整演示场景是任务管理示例的“创建任务”：React 表单提交标题，DRF 接口校验标题，合法输入写入数据，返回结果并更新页面；缺失、空字符串及纯空白标题均应被拒绝，且不新增任务。

M26 取消练习和实验执行。对无法识别接口的源码，仍提供只读阅读、独立知识识别和明确诊断。

### 3.2 能力覆盖

| 层次 | v0.1 承诺支持 | 超出支持范围时的行为 |
| --- | --- | --- |
| Python | 合法源码中的定义、导入、静态属性和直接引用 | 记录单文件语法错误或未解析关系，保留其他结果 |
| DRF | 字面量 `path/include`、标准 `SimpleRouter/DefaultRouter` 注册、直接 `as_view`、固定 `serializer_class`、`ModelSerializer.Meta.model` | 动态路由、动态选择序列化器和复杂运行时分派标为未解析 |
| React | JS/TS/JSX/TSX 中 `fetch/axios` 的静态方法、路径，以及可解析的本地直接调用 | 运行时拼接、动态代理、多层复杂封装不自动补全 |
| 前后端关联 | 静态方法与路径的唯一匹配，并保留前后端来源 | 多个候选或基础路径未知时保留候选及原因，不任意选取 |
| 讲解 | 选定接口、相关代码证据、有限知识卡片 | 缺少证据时说明缺口，不补造路径或作者意图 |
| 学习 | 内置示例的流程排序、错误预测、代码定位练习 | 其他项目提示尚无对应练习，不伪造标准答案 |

静态关联表示根据代码推导的可能关系，不能称为实际执行记录。识别完整也只指已声明的规则范围，不代表程序全部运行路径都已恢复。

### 3.3 明确非目标

首版不包括任意项目自动运行、自动改代码、通用多语言分析、编辑器插件、多人协作、收费系统、公网多租户、自动生成完整课程、通用运行链路采集、人工修正关系图和快照差异分析。后两项及其他扩展的安排见[总体路线图](roadmap.md)。

## 4. 功能需求

<a id="fr-01"></a>
### FR-01 导入与源码快照

- 用户上传 ZIP 或选择源码目录，在同一个表单中创建项目或导入已有项目；名称默认取来源名称并可修改，成功后生成不可变快照并自动扫描。
- 用户可显式保存快照名称到服务端；名称仅为展示元数据，源码、文件摘要和分析引用仍保持原快照。历史未命名快照显示明确状态与真实日期，不以编号冒充名称。
- 每次导入生成独立快照，重复导入不覆盖旧快照；失败导入不能替代最后一个可用快照。
- 展示接收、排除、跳过和拒绝的文件概况，避免在错误中回显敏感文件内容。
- 环境文件、密钥、版本控制元数据、依赖目录、构建产物和二进制文件不进入代码分析与模型上下文。过滤不能保证识别所有硬编码秘密，发送前仍须可检查片段。
- 违反归档安全或总资源限制时拒绝整次导入并清理暂存数据；普通不支持文件跳过并列入摘要。
- 文件范围和默认资源上限由[后端规范](backend-guidelines.md#import-boundary)统一维护。
- 验收：AT-01、AT-02、AT-03、AT-21。

<a id="fr-02"></a>
### FR-02 DRF 接口与代码识别

- 用户看到识别出的接口方法、路径、处理类或函数及源码证据。
- 对支持范围内的示例，关联路由、视图、序列化器和模型，并区分用户源码与框架默认行为。
- 分析结果包含规则版本、文件诊断和覆盖说明；不执行项目来获取运行时路由。
- 部分文件无法解析时返回可用部分与诊断；关键依赖不可用或无法产生可靠结果时任务失败。
- 验收：AT-04、AT-05、AT-06。

<a id="fr-03"></a>
### FR-03 React 请求与接口关联

- 用户可以从后端接口查看相应 React 请求位置及可识别的入口函数。
- 关联使用静态 HTTP 方法和路径；未知基础地址、前缀或动态参数不能静默猜测。
- 多个候选保留为候选，不作为已确认连接；无匹配时显示原因及相应源码。
- 验收：AT-07、AT-08。

<a id="fr-04"></a>
### FR-04 流程与源码工作区

- 项目管理负责入口、快照和删除；统一工作区联动文件/接口导航、双源码及接口、关系、知识和讲解面板；操作日志负责追溯。
- 节点能定位到所属快照的相对文件路径和行号；框架概念说明不能伪装成用户源码引用。
- 显式区分源码事实、静态推断、通用原理和内置实验观测；图中断点与候选关系可辨认。
- 切换快照或接口后不显示旧对象的结果；直接链接不可用时给出明确反馈。
- 验收：AT-09、AT-10、AT-23。

<a id="fr-05"></a>
### FR-05 带证据的模型讲解

- 讲解围绕“做什么、依据在哪里、为什么这样工作、相关知识、如何验证”组织。
- 先生成待发送的上下文预览。确认绑定快照、片段、目标服务和模型；这些内容变化后重新确认。
- 用户拒绝发送时不调用模型，仍能浏览静态结果。模型无执行命令、读任意文件或修改项目的能力。
- 模型用户配置仅保留请求地址、模型 ID 和 API key；应用不设输入/响应字节预算、输出 token 上限或请求总期限，不发送限额参数。供应商默认限制及费用由用户判断；预览显示实际发送范围和字节数，结果分别记录报告的输入、输出和总用量，未知用量不估算。
- 返回内容进行格式、引用归属及行号范围校验；没有有效依据的项目事实不得作为确认结论展示。
- 区分引用位置有效与解释正确。讲解显示所用快照、生成时间和模型标识，不承诺消除幻觉。
- 模型未配置、不可用、超时或返回异常时保留已有结果，提供明确错误；存在潜在计费的请求不自动重复发送。
- 验收：AT-11、AT-12、AT-13、AT-14。

<a id="fr-06"></a>
### FR-06 固定练习与学习记录（已退役）

以下为历史定义，M26 不再提供执行或写入，仅保留必要历史读取。

- 首版为内置示例提供三类练习：流程排序、错误预测、关键代码定位，每类至少一题。
- 题目与经人工核对的示例版本、答案和解释绑定；练习要求先提交预测，再展示答案。
- 保存每次作答，不用新答案覆盖历史；题目版本变化后旧记录仍保留所属版本。
- 开放式回答可以提供建议，但不据此自动认定掌握程度。不因用户答错而修改标准答案。
- 知识卡片由人工维护首批内容，覆盖当前功能所需的 HTTP、校验、序列化、ORM 与 React 状态基础；系统性知识路径安排在 v0.3。
- 验收：AT-15、AT-18。

<a id="fr-07"></a>
### FR-07 内置请求校验实验（已退役）

以下为历史定义，M26 不再提供执行或写入，仅保留必要历史读取。

- 用户先预测正常标题和空标题的响应、是否写入数据，再启动固定实验。
- 展示实验来源、输入、实际请求与响应、写入变化及执行时间；实验数据仅限无敏感内容的内置示例。
- 内置应用独立于导入项目；工作台只调用固定实验接口，不接受任意脚本、镜像、命令或目标地址。
- 每次运行具有独立数据范围，重复运行与并发不会污染其他实验；清理仅针对该运行生成的数据。
- 示例未启动、连接失败或结果不完整时显示失败或未完成观测，不能使用预设结果代替实测。
- 验收：AT-16、AT-17、AT-22。

<a id="fr-08"></a>
### FR-08 任务与结果持久化

- 刷新或重新进入项目后可查看持久化的快照、任务、讲解、作答与实验记录。
- 任务使用 `queued`、`running`、`succeeded`、`failed` 四种状态；详细规则仅由 [API 契约规范](api-conventions.md#job-contract)定义。
- 失败后重试创建新的尝试并关联旧记录；重复提交同一请求不能产生重复的有效任务。
- 队列发布失败、Worker 中断或运行超时不能让任务永久停留在处理中；定期核对并给出原因。
- 显示真实阶段。没有可计算总量时展示阶段和已处理数量，不显示虚构百分比。
- 验收：AT-18、AT-19、AT-20。

M1-T02 使用经确认的固定“基础链路检查”验证 FR-08 和本地匿名写操作保护：不接受业务输入、不读取源码、不调用模型，不替代 M1-T03 的标题业务示例。任务与结果接口见 API 清单 4.5；完整重试与业务恢复仍归所属后续任务。

<a id="v02-requirements"></a>
### v0.2 功能需求

以下需求延续本地单用户、同栈、只读导入及既有 NFR。人工关系仅作用于关系展示和影响分析，不进入模型上下文；不新增图编辑、任意补边、其他框架或运行导入源码能力。

<a id="fr-09"></a>
### FR-09 同栈规则扩展与评估

- 支持标准 Router 的字面量 `@action`：明确的 detail、methods、url_path 及直接指定的 serializer_class；框架允许省略的参数使用已锁定版本默认值，动态参数和不合法写法保留诊断。
- 支持完全由字符串字面量及不可变常量组成的模板 URL；运行时变量、环境配置、参数化请求封装和未知目标不自动补全。
- 每种支持写法保留正例、反例、源码及框架依据；开发样例与评估样例分离，先记录旧规则基线，再报告正确识别、错误关联、漏识别、候选、不支持项和分母。
- 本版按用户授权采用编码代理复核的分离合成集，记录复核角色及样例版本；不冒称独立人工标注或真实用户项目评估。
- 新规则生成独立分析，旧结果保留原版本，不回填；有限评估集的错误自动确认逐项解决，旧支持规则不得回归，不预设准确率。
- 验收：AT-26、AT-27、AT-28。

<a id="fr-10"></a>
### FR-10 人工确认候选关系（已退役）

以下为历史定义，M26 不再提供执行或写入，仅保留必要历史读取。

- 只允许确认、排除或撤销当前分析已有的前端请求—后端接口候选；每个请求最多确认一个目标，未选择的候选不自动排除。
- 追加保存动作、归属、时间和修订号，保留历史；并发旧修订明确冲突，重复提交不重复追加，不覆盖原始静态图。
- 区分自动静态匹配、人工确认、未决候选和人工排除，人工判断不变成源码事实或运行观测。
- 不跨分析或快照自动迁移决定；模型预览和讲解继续沿用原静态证据，不应用人工决定，界面说明该范围。
- 验收：AT-29、AT-30、AT-37。

<a id="fr-11"></a>

- 顶部搜索框直接输入，有效关键词完成防抖后在原框下方非模态显示对应结果，不先点击放大；空值或纯空白不显示下拉，清空立即隐藏并取消请求，换词期间不显示旧结果。搜索全部项目名称、当前快照文件路径和当前分析 method/path。项目/接口服务端 q 子串匹配、最多 200 字符、原索引保留，文件使用完整清单。分组独立批次，支持防抖/中文组合/取消/键盘，源码独立筛选保留。
- 通知从 succeeded/failed 任务派生，历史初始未读，前台 5 秒读取、后台暂停；打开和查看零已读写入。显式单条或全部已读服务端保存，全部已读单调推进至列表读取 as_of，此后完成仍未读；未知结果读取核实，禁止自动重试。

<a id="fr-26"></a>
### FR-26 导入、根发现与自动衔接

- ZIP 上限 20 MiB。浏览器目录选择提交相对路径清单和有效文件；最多 2000 个有效文件、每文件 1 MiB、合计 100 MiB、清单 4 MiB。代理上限 110 MiB，内部归档预算 105 MiB。
- 前后端均排除环境、依赖、构建与敏感文件并验证路径。服务端标准库生成确定性内部归档，复用快照发布和恢复；来源及限额持久化，目录重试重新选择原目录。
- 优先采用静态 Django 设置和字面量 ROOT_URLCONF；其次使用 urlpatterns/include 顶层关系。唯一根自动分析，多根列出证据供选择，无根仍可阅读源码与知识。
- 扫描、准备状态和后续分析在同一事务关联，提交后投递。刷新或关闭浏览器不中断任务；失败保留快照，显式重试无需重传。
- 验收：AT-84–87。

### FR-27 接口源码关联

- “接口关联”使用接口 ↔ 共用处理器/序列化器/模型共享节点，身份由源码位置确定，采用无向遍历；“代码依赖”保持原有方向。
- 每条连接有依据，可定位双方源码，展示图范围、预算与截断。不得推断业务执行先后顺序。
- 验收：AT-88。

<a id="fr-28"></a>
### FR-28 快照知识与可信内容

- 独立扫描真实 AST 的装饰器、上下文管理、推导式、生成器、异步、异常、模式匹配、类型注解及支持的 Django/DRF 概念；注释与字符串不作为语法命中。
- 包事实区分本地、标准库、已知第三方和未知导入；首批卡片涵盖 Django、DRF、requests、httpx、asyncio、dataclasses、contextlib、functools、collections。
- 受控解析 requirements*.txt 和 pyproject.toml，不安装依赖或查询用户环境；外部地址只记录脱敏诊断。卡片/命中绑定扫描版本，展示原因、引用、覆盖和截断，可筛选全快照/文件/接口。
- 未映射事实不编造正文。旧分析不自动回填；新实例仅加载卡片。讲解预览包含保留源码范围内的卡片版本，排除片段同步排除知识，旧确认失效，旧讲解可读，模型输出不更新可信内容。
- 验收：AT-89–91。

### FR-29 永久删除与独立操作日志

- 删除先预览内部范围，再显式确认，后台四态执行。仅清理归属明确的内部源码、暂存和关联结果，原 ZIP/目录、其他项目、全局卡片保持。
- 接收或排队/运行任务存在时返回冲突；删除期间拒绝目标的新读取/分析/模型提交。持久化内部 UUID 清单、阶段和当前尝试，文件失败保持隔离，显式“继续清理”创建新尝试，重复请求复用原操作。
- 涉及被删快照的历史比较整条删除，另一侧快照保留；日志和必要任务摘要独立保存，结果显示“已删除”，迟到请求取消、相关选择和缓存清除。
- 日志覆盖导入、扫描、分析、模型、删除的接收、前置拒绝、异步失败、重放，保存对象名称/ID、时间、阶段、稳定错误和任务；可按项目、类型、结果和时间筛选。
- 浏览器未提交、代理先拒绝或数据库不可用时，不承诺已形成可靠应用记录。
- 验收：AT-92–95。

## 7. 风险与技术验证

- 静态规则不能恢复全部动态行为；扩大支持范围必须增加标注样例及回归测试。
- 有效引用不保证讲解正确，需人工评审代表性内容；自动校验只能覆盖可验证的边界。
- 非流式模型请求存在耗时、费用和返回结构差异；实际供应商通过兼容用例后才进入支持清单。
- 默认资源限制是防御性起点，不是性能承诺；在参考设备与明确输入规模下调整并记录依据。
- Docker 用于受控示例的可复现运行，不承担任意第三方代码执行平台的安全承诺。
- 上述技术验证分别纳入开发计划 M1-T01、M2-T02、M3-T01、M4-T01 和 M5-T03；尚未实测不构成扩大范围的理由。
