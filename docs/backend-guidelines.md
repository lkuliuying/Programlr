## 1. 依据与技术组合

### 1.3 官方 wheel 缓存与离线验收

用户已选择把下载准备与安装分开计时。根目录执行 `python -X utf8 scripts/prepare_backend_wheels.py --platform all`，仅按当前 `uv.lock` 中的官方 URL、大小和 SHA-256 下载；使用锁中已有的 packaging 纯 Python wheel 引导，并在两个实际参考解释器中读取兼容标签，选择对应分发，不增加直接依赖。下载并发为 2，单次最多 300 秒，每个文件最多 3 次，整轮最多 1800 秒；保留可续传分片，失败非零退出。不得把下载准备耗时算作安装通过证据。

完整校验的缓存按平台和锁摘要存放于 `.runtime/backend-wheelhouse`；派生 requirements 使用 `uv export --locked --offline --all-groups --no-emit-project` 生成，不构成第二套依赖依据。缓存安装通过 `uv pip sync --no-index --offline --find-links … --require-hashes --only-binary :all:`，然后 `uv sync --locked --offline` 核对工程环境。安装总期限仍为 600 秒，后端检查组总期限为 300 秒；缺包或摘要错误不会联网回退，Linux 后端缓存验收容器另使用 `--network none`。

缓存选择使用的 packaging 26.3 已是当前锁文件中的传递开发依赖，官方 wheel 元数据许可为 `Apache-2.0 OR BSD-2-Clause`；它只承担 wheel 标签解析，不成为新直接依赖或浏览器运行依赖。缓存增加可恢复下载的磁盘占用，收益是网络下载不会因安装进程整体超时而反复丢失进度；缓存不能代替每个平台的实际安装与工具检查。

总入口新增 `-BackendInstallSource Wheelhouse`，原在线模式 `Online` 仍是默认值。Windows 缓存模式在本次报告目录中新建验收虚拟环境，保留原 `.venv`；Linux 使用固定镜像内的新虚拟环境，只读挂载 wheel 缓存，不共享 Windows 安装。实际通过范围及冷热缓存条件见阶段计划，不承诺冷缓存联网安装可在 600 秒内完成。

### 1.4 M1-T02 必要依赖与运行入口

本任务保留所有原有依赖版本，新增 Celery 5.6.3（BSD-3-Clause）、psycopg/binary 3.3.6（LGPL-3.0-only，二进制所带组件保留各自许可）、Gunicorn 26.2.0（MIT）、drf-spectacular 0.30.0（BSD-3-Clause）。分别用于既定 Redis Worker、PostgreSQL 驱动、容器 WSGI 服务和本任务接口契约；没有另建业务框架。Redis Python 客户端由 Celery extra 约束，锁定结果为 6.4.0。

服务镜像使用 PostgreSQL 17.9 Bookworm（PostgreSQL License）、Redis 7.2.13 Bookworm（BSD-3-Clause）与 Nginx 1.30.3 Alpine（BSD-2-Clause）；Python/Node 延续 M1-T01 版本。Compose 固定实测镜像摘要。版本选择未声称采用全部软件的最新发布；运行兼容性由真实构建、数据库事务和 HTTP 故障验收验证。来源：[Celery](https://pypi.org/project/celery/5.6.3/)、[Psycopg](https://pypi.org/project/psycopg/3.3.6/)、[Gunicorn](https://pypi.org/project/gunicorn/26.2.0/)、[drf-spectacular](https://pypi.org/project/drf-spectacular/0.30.0/)。

`jobs` 当前只拥有固定基础检查的技术结果，后续业务结果仍归各业务模块。事务外投递、数据库唯一键、原子领取与完成时资格核对共同维持基础幂等。独立 `reconcile_jobs --loop` 每 5 秒核对排队/执行期限，启动立即核对；数据库不可用时记录安全诊断并等待恢复。API-17 的现有任务重试见 6.3；后续业务不在当前恢复验收范围。

`common/middleware.py` 在 DRF 分派前使用标准 Django CSRF 对固定非豁免目标校验；匿名请求也要求精确 Host/Origin，忽略客户端转发头。`config/environment.py` 读取受控进程配置和互斥的 `*_FILE`，拒绝无效值。启动见 [README](../README.md)，Compose 的数据库、队列和后台进程不发布宿主端口。凭据在私有命名卷生成，源代码、日志和文档不保存实际值。

数据库聚焦测试从根目录执行 `docker compose run --rm --no-deps api python -m pytest apps/jobs/tests tests --ds=config.settings.local -q -p no:cacheprovider`。后端静态检查覆盖 `config common apps tests`；mypy 使用无数据库的 `config.settings.test` 加载 ORM 类型，仅对缺少声明的 Celery/Kombu 导入设置例外，不关闭业务严格检查。容器以非 root 用户运行、根文件系统只读，mypy 缓存放在 `/tmp`。质量工具包含在本地镜像内，尚未建立发布裁剪。

本任务从 Serializer/View 导出已实现接口；固定空对象的请求正文仍必填，由 `SystemCheckSchema` 明确声明并通过契约测试约束。生成位置不变，不为未来接口输出假 Schema。M1-T04 已整理工作台及独立示例的现有契约，实际验收见阶段计划。

### 1.5 独立教学示例

`examples/task-board/backend` 使用独立 pyproject/uv.lock，复用 Python、Django、DRF、psycopg、Gunicorn、drf-spectacular 及质量工具的已锁定版本与许可证，不引入 Celery/Redis。简单业务保留 View → Serializer → service → ORM 边界，数据库保存任务和唯一幂等键；标题规范化在 HTTP 校验层完成，数据库另设非空白约束。服务独立配置和复用设计的错误/CSRF 实现均在示例内，不运行时依赖工作台。独立 Cookie 名防止本机同主机不同端口互相覆盖；精确 Host/Origin 仍必需。

示例 PostgreSQL、秘密和网络与工作台分离；没有运行标识、实验清理或固定实验接口，M5 再按运行隔离。人工基准的源码事实、静态匹配和框架推导分开，引用完整性检查不是解析器。示例命令、契约路径和原键恢复限制见[示例说明](../examples/task-board/README.md)，实际证据仍只在阶段计划。

### 1.6 M1 契约检查基线

两服务的 `common/schema.py` 维护公共响应头、406/500 错误、页码边界与 UUID 幂等键声明；不反向依赖业务模块，也不建立两工程之间的运行依赖。各业务 Schema 只补生成器无法推导的已有规则：工作台空对象正文必填、示例额外字段拒绝和标题规范化说明。示例补充 Django 路由层 404/500 JSON 处理，406 使用明确 `NOT_ACCEPTABLE`；其余业务、持久化与访问保护不变。

各自 `test_contract.py` 可通过 `python -m pytest apps/jobs/tests/test_contract.py --ds=config.settings.test -q -p no:cacheprovider` 或示例的 `apps/tasks/tests/test_contract.py` 无数据库执行。`test_contract_responses.py` 验证 PostgreSQL 真实创建、重放、冲突/任务失败与查询的响应形状；使用 local 配置及临时测试数据库。响应校验复用 drf-spectacular 锁中已有的 jsonschema，根检查脚本复用已有 PyYAML，未增加依赖；第三方无声明导入采用精确 mypy 例外，业务严格检查保留。

根 `scripts/check_contracts.py` 有子进程期限，导出到临时目录后比较，任何漂移或命令失败非零退出。它不自动覆盖产物，完整工具选择与命令见 [README](../README.md)。M2–M5 协议仍按所属任务建立，不能把 M1 检查结果当作完整 NFR 或业务验收。

## 2. 架构与模块职责

采用模块化单体，Web API 与 Worker 分进程运行，共享经明确约定的业务模块和持久化数据。业务按以下职责分组，名称是目标模块，不代表当前已有目录。业务代码放在 `backend/apps/`，Worker 复用这些模块，不另建业务工程；`backend/common/` 只放公共技术能力。模块内文件按需创建，单文件拆为职责包时不保留同名文件和包。

| 模块 | 负责 | 不负责 |
| --- | --- | --- |
| projects | 导入、过滤、快照与受控源码读取 | 执行导入项目 |
| analysis | 解析器编排、规则、图、诊断和证据 | 自行解释用户未授权发送的代码 |
| explanations | 上下文选择、外发确认、模型适配、输出校验 | 文件任意读取、命令执行、Agent 工具调用 |
| learning | 知识卡片、固定练习、答案版本与作答 | 凭模型分数自动判定掌握程度 |
| labs | 固定内置实验调用与观测记录 | 操作任意项目、任意 URL 或宿主 Docker 控制面 |
| jobs | 持久化任务、领取、状态转换与失效核对 | 承载各业务域全部实现 |

- View/路由负责 HTTP、来源与权限边界、请求响应组织，不承载长时解析或模型调用。
- Serializer 校验输入输出的形状和边界；跨步骤业务由服务层组织。
- ORM 和数据库约束共同维护唯一性与关系完整性；事务范围不包含远程模型或实验网络调用。
- 简单 CRUD 使用 DRF 现有能力，不机械添加 Repository、抽象基类或转发层。
- 解析器、图算法和上下文选择中的纯逻辑不依赖 HTTP，可用普通输入与固定样例单测。
- 模块之间通过明确服务入口传递标识和结构化结果，不直接操作其他模块的内部状态。

## 3. 命名、类型与错误处理

Python 文件、包和普通标识符使用 `snake_case`，类使用 `PascalCase`，具体例外见[命名规范](project-structure.md#naming)。公共函数、跨模块输入输出和复杂数据结构添加类型标注。新注释、实质改写的注释和 docstring 使用简体中文，解释决策、约束和风险，不重复代码本身。

Model 维护持久化，`api/serializers.py` 维护 HTTP 输入输出，模块内 `types.py` 维护内部数据形状，不把三者混为同一对象。Schema 输出到 `contracts/openapi.yaml`；Node 解析输入输出由 `contracts/typescript-analysis.schema.json` 约束，两端运行时校验，生成文件和协议源的区别见 [API 清单](api-catalog.md)。

可预测错误转换为明确领域错误，并在 HTTP 或任务边界映射为统一错误对象。未知异常在边界记录脱敏诊断和 `request_id`/任务标识，客户端收到稳定错误，不接收栈、宿主路径、源码正文或凭据。

禁止捕获异常后返回空列表、成功状态或预设实验结果。单文件解析错误可以降级为诊断并继续处理其他文件，但必须进入覆盖摘要，不能被忽略。

文件、数据库连接、子进程与 HTTP 客户端有明确所有者，使用上下文管理与 `finally` 完成回收。子进程使用固定可执行文件和参数列表，不拼接 shell 命令；非模型子进程限制输出体积和运行时间，模型等待不设总期限，丢失领取或异常退出时回收。

## 4. 导入边界与快照

### 4.1 默认资源限制

下表是 v0.1 的初始防御性默认值，尚未经性能测试；唯一维护位置为本文。M1-T01 固定名称和数值，执行限制由 M2/M4 等对应任务落实；M5-T03 根据参考设备记录实际表现。资源上限不是支持任意规模项目的承诺。

| 项目 | 默认上限 | 超限行为 |
| --- | --- | --- |
| ZIP 压缩体积 | 20 MiB | 拒绝上传 |
| 声明解压总量及实际解压总量 | 各不超过 100 MiB | 拒绝导入，清理暂存 |
| ZIP 全部条目 | 5,000 项 | 拒绝导入 |
| 可分析源文件 | 2,000 个 | 拒绝导入，提示缩小范围 |
| 单个可分析源文件 | 1 MiB | 拒绝导入，提示具体限制，不回显文件内容 |

源文件首版包括 `.py`、`.js`、`.jsx`、`.ts`、`.tsx`；仅额外接收有明确用途且经校验的非秘密说明或清单文本。元数据读取不能触发其项目行为。允许项与排除项同时生效，排除规则优先。

排除 `.env` 及 `.env.*`、密钥/证书文件、凭据文件、`.git`、依赖与虚拟环境目录、构建产物、缓存和二进制。对于未被文件名规则发现的硬编码秘密，在外发前再检查并让用户审阅；不能声称过滤已保证源码不含秘密。

### 4.2 归档安全

- 不信任 ZIP 文件名、声明大小、压缩率或 MIME。拒绝绝对路径、盘符/UNC、路径上跳、NUL、链接条目、加密包及含糊路径。
- 将路径分隔统一后检查；拒绝重复规范路径和跨平台大小写冲突，保证 Windows 与 Linux 不产生不同覆盖结果。
- 安全检查覆盖全部条目。忽略文件的恶意路径不能成为绕过条件；记录实际读取/展开字节，不能只依赖包头大小。
- 在专用暂存目录处理，最终路径必须位于授权根下。不读取用户提供的宿主绝对路径，不跟随符号链接。
- 接收流、解压、解码、文件数和解析器运行都必须有界；不支持的普通文件列入摘要，危险结构或总量超限拒绝整次导入。

### 4.3 快照发布与读取

先完整验证并准备内容，再发布可见快照。数据库和文件系统不具备共同事务，必须采用暂存、完整性标识与恢复扫描，使中断后只出现可清理暂存或完整快照，不能出现可读取的半成品。

每次导入具有独立快照 ID；内容、文件哈希、行号索引与编码解释在该快照内不可变。已发布快照不原地改写，不因新导入成功而删除旧记录。

用户追加的快照 `name` 是可编辑展示元数据，使用 `projects/0002_snapshot_name` 增量字段，旧记录保留空名称。重命名服务仅 `save(update_fields=["name"])`，不得改写清单摘要、源码、导入任务、时间或分析引用；同源 PATCH 只接受经过严格校验的名称。完整契约和验证分别见 API 清单及第四阶段计划，不在导入 multipart 中追加字段。

源码读取接口以快照与文件标识定位，服务端再通过快照的文件清单与受控相对路径解析；用户输入的路径不能直接拼接为宿主路径。缺失文件、越界行号或不属于该快照的引用明确拒绝。失败暂存可清理，成功快照和学习记录首版不做隐式淘汰；未来删除功能单独定义。

### 4.4 M2-T01 的实际存储协议

`projects` 只接受 `.py/.js/.jsx/.ts/.tsx`，首版不额外接收说明或清单文本；不支持编码、二进制和普通其他文件跳过。UTF-8/BOM 解码后统一 LF，哈希/大小/行号描述该规范化版本；空文件为 1 行。行索引每 128 行记录一个字节偏移，避免大量短行消耗过多元数据内存。支持范围与逐项 HTTP 字段见 API 清单 4.8。

先有界检查中央目录条目数，再交给标准库校验本地头及重叠区域；全条目统一路径并检查大小写、Unicode 规范、设备名、文件/目录冲突。直接对 STORE/DEFLATE 压缩段分块计数，验证实际长度和 CRC，避免伪造声明长度截断后漏计膨胀内容。被排除的条目也经过安全校验与展开计数，但不写入有效快照。解码和过滤不执行源码。

Linux 私有卷固定为 `/var/lib/learning-lab/imports`；`staging/<随机标识>` 保存有界上传，快照文件以随机 file_id 命名，原相对路径仅在清单中。上传锁保护尚未写入数据库的暂存；数据库可靠提交且释放上传锁后才投递，防止快速 Worker 丢失执行机会。`jobs` 用 `(scope, idempotency_key)` 唯一约束，旧任务迁移后 scope 为 system_checks_create；导入 scope 绑定项目。上传文件名不参与请求摘要。

全部文件 fsync、完整性清单写入并同步目录后，同卷 rename 到 `snapshots/<snapshot_id>`。Worker 持有文件锁，jobs 服务锁定有效领取；文件发布与 Snapshot/SourceFile/成功任务在数据库事务边界核对资格，发布后再次检查期限。文件系统与 PostgreSQL 没有共同事务，先 rename 后数据库可见；提交不确定时以数据库为准，不能直接删除可能成功的结果。每 5 秒及启动时，现有核对进程先终结超期任务，再跳过仍锁定/有效任务，清理无主或失败暂存及不可见完整目录；不会删除已发布快照。删除仅针对私有根内服务端 UUID 目录。

受控读取验证 snapshot/file 归属、完整性清单、文件类型/长度/摘要，拒绝符号链接，按保存的行索引返回 JSON 文本；请求路径不能变成宿主路径。单次最多 500 行、默认最多 200 行，内容另受单文件上限约束。没有模型适配器或外发入口，后续上下文必须使用此清单/读取服务，不能读取暂存 ZIP。已发布内容无更新/删除 API；过滤不是秘密识别保证。

运行只支持已约定的 Linux 容器；使用 flock、O_NOFOLLOW、目录 fsync。Windows 可运行纯归档测试和契约导出，但不作为原生存储/Worker 平台。Windows 的 mypy 使用 `--platform linux` 检查实际运行 API，Linux 上默认平台即可；不关闭严格类型检查。根文件系统保持只读，存储仅使用新私有卷，不映射用户源码目录。当前执行只在隔离测试环境验证，不自动迁移或重启已有业务服务。

依据：标准库 ZIP 提取会修正部分危险路径，因此本实现使用显式拒绝及受控文件标识；同文件系统 rename 提供原子目录可见性，但不代替数据库事务。[Python ZIP 文档](https://docs.python.org/3.13/library/zipfile.html)、[os.rename 文档](https://docs.python.org/3.13/library/os.html#os.rename)。

## 5. 解析、关联与证据

Python 使用 `ast` 处理语法；`analyzers/typescript/` 中的独立 Node 解析器通过受控子进程 stdin/stdout JSON 通信，使用 TypeScript Compiler API 读取给定源码文本，不增加 HTTP 服务。解析过程不得加载用户配置插件、执行包脚本或在用户工作目录安装依赖。

支持矩阵以[需求文档](requirements.md)为准。DRF Router 生成的标准动作属于已知框架规则推导，必须同时保留注册位置及规则依据，不能伪造用户代码中不存在的方法位置。

React 请求关联保留原始方法/路径、归一化依据及候选。路径大小写、尾斜杠、基础前缀或代理重写可能具有语义，不通过随意删除它们获得匹配。只有静态可证明的变换可进入确认关联；无法确定时展示候选或缺口。

图使用邻接关系和数据库记录存储；节点、边与引用绑定快照和规则版本。BFS/DFS 使用访问集合处理环，限制展开量。结果截断或未解析关系必须对用户可见。

源文件解析失败、部分框架写法不支持和整体分析服务故障分别处理。允许返回部分图时任务可成功，但结果带有诊断与覆盖说明；任务成功不等于所有路径均被识别。

### 5.1 M2-T02 已建立的静态分析边界

`analysis` 以根路由文件的清单相对路径为显式入口，只读取已发布快照并校验原摘要。`python_index.py` 构建 AST、导入别名、定义和静态属性索引；`drf_rules.py` 处理视图/序列化器/模型；`parser.py` 展开路由及标准 Router。唯一模块才解析，重名模块、重复绑定、条件属性、动态选择和自定义分派保留诊断；不执行导入、eval、依赖安装或项目配置。

支持字面量 path/include、列表拼接、相对/别名导入、APIView 与标准 GenericAPIView、直接 ViewSet.as_view 方法映射、SimpleRouter/DefaultRouter 的六种标准动作、标准 mixin 和直接用户继承。固定 serializer_class、ModelSerializer.Meta.model 可关联；框架隐式动作保留注册证据与 `drf/3.18.1.*` 依据。DefaultRouter API 根/格式后缀、HEAD/OPTIONS 显式标为框架推导；正则模式保留 `$`、lookup 表达式及转换器语义，不视为运行时 URL。自定义 action、动态注册、外部包、复杂多用户基类、运行期设置和任意猴子补丁不承诺恢复；结果始终附限制。

纯解析结果通过固定 `worker.py` 进程生成；`runner.py` 使用当前可信解释器、`-I` 和固定脚本路径，不在导入目录运行。Linux 子进程默认地址空间 768 MiB、CPU/父进程期限 60 秒、输出 8 MiB，AST 总节点 500,000，接口及诊断各 10,000，协议输入 128 MiB；超过预算整体失败，不返回截断成功。这些是防御上限，不是容量实测承诺。父进程超时终止并等待回收；stderr 不保留用户源码或 traceback。`protocol.py` 再核对形状、规则版本、计数、快照归属及行号范围。

单个非根文件语法错误保留其他结果并记诊断；根文件不可解析、受控读取失败、进程崩溃/超时或非法协议使任务失败。数据以 AnalysisRequest/Analysis 存储，结果和任务成功状态在同一事务内发布，终态或领取期限失效时拒绝迟到结果。`jobs` 仍拥有执行资格；图见 5.2，API-17 的恢复与重试见 6.3。没有新增依赖或锁文件变更。

规则依据同时核对当前锁定包源码与 [DRF Router 文档](https://www.django-rest-framework.org/api-guide/routers/)；AST 的栈/内存风险依据 [Python AST 文档](https://docs.python.org/3.13/library/ast.html)，因此不把 ast.parse 当作无资源风险的内联操作。导入项目实际框架版本未通过执行验证，覆盖摘要明确规则适用版本。

### 5.2 M2-T03 图存储和遍历边界

`graph.py` 是独立于 Django 的纯构图、校验与邻接遍历模块；输入为 M2-T02 已验证的结果，不重新执行或解析导入代码。只投影 endpoint/view/serializer/model 和三类有证据的关联，包含链、注册及框架动作保留为证据，不扩展 service/ORM 或前端规则。共享符号去重，重复接口保留候选；未解析引用不补造边。

AnalysisGraph 以一对一分析关系保存 graph_version、nodes 和 edges JSON，快照与解析版本由不可变 Analysis 关联继承。保存前及读取时校验结构、唯一标识、非悬空边、非空证据、快照归属与文件行范围；损坏的持久化图返回统一 500，不降级为空图。新增迁移不回填历史图，旧分析仍可读；图缺失与有效空图使用不同响应，详见 API 清单 4.10。

图资源上限在本节维护：保存最多 40,000 节点、30,000 边及 32 MiB UTF-8 JSON；超过预算以 ANALYSIS_FAILED / graph_limit 结束，不能保存截断结果。图查询默认 200 节点、400 边，最大 1,000 节点、2,000 边。预算是初始防御值，未作为产品容量实测。构图和校验在发布事务前完成，Analysis、AnalysisGraph 与任务成功在现有 complete_analysis 事务中一起发布；图写入失败全部回滚，过期/失效领取不可发布。

BFS 使用 deque，DFS 使用显式栈；访问集合处理环，不递归枚举路径。遍历前建立邻接关系并稳定排序，只在选中节点之间返回原有边，保留自环/回边和孤立节点。指定根只沿出边，无根遍历各分量；预算造成遗漏时标记原因，主动聚焦根不算截断。稳定排序有额外成本，不能将整个查询描述为纯线性过程。GET 不写库、不解析、不回填、不提交任务；图可达性不代表运行轨迹。

## 6. 持久化与任务可靠性

### 6.1 数据约束

业务记录以 PostgreSQL 为准。快照、任务结果、讲解、题目版本、作答和实验记录之间保留稳定引用。具体字段在所属里程碑的接口与数据设计中确定，不将文档概念表直接宣称为现有数据库。

任务记录先在数据库事务中提交，再投递队列；不得让 Worker 读取尚未提交的数据。投递失败需记入任务失败原因，提交后进程崩溃造成的间隙由期限核对覆盖。大型源码正文放在受控文件存储，不塞入队列消息。

### 6.2 状态与重复执行

任务转换、HTTP 行为和幂等键以 [API 规范](api-conventions.md#job-contract)为唯一来源。Worker 通过数据库的条件更新或锁原子领取；同一任务只能有一个有效执行资格。

每次执行具有可验证的领取标识与期限，写回结果时再次验证资格和状态。任务已失败或被判定失效后，旧 Worker 的迟到结果不能覆盖终态。任务结果发布和成功状态须保持一致，不能先成功后再保存内容。

任务配置排队期限，非模型任务配置固定执行期限，模型等待持续续期领取且不设总执行期限。由受控定时核对逻辑扫描过期领取，在重启时也执行核对；核对必须可重复执行，避免重复补偿。默认运行一个执行槽位，长时间模型等待会占用该槽位，后续增加并发需要先验证数据隔离和资源预算。

超时失效后首先失败留痕，不静默重放潜在计费的模型请求或有副作用的实验。用户显式重试创建新任务，保留旧任务关系。导入/分析内部的确定性局部处理可做有界重试，但不能掩盖最后失败原因。

Celery 提供任务投递与执行机制，业务幂等性与故障恢复仍需应用明确设计；不能从采用队列推出“恰好一次”。[Celery 任务文档](https://docs.celeryq.dev/en/stable/userguide/tasks.html)

### 6.3 M2-T04 当前恢复与重试边界

Job.previous_job 是可空 PROTECT 自关联，新迁移不回填或重置旧任务。`jobs/retries.py` 协调原请求读取及业务服务，`jobs/services.py` 保存重试任务及执行资格；projects/analysis 仍通过各自 service 创建请求与业务结果，不把持久化结果迁入 jobs。重试范围为 jobs_retry:原任务 UUID，唯一键和同一事务中的业务请求保证并发同键只产生一个任务并投递一次。

M2-T04 当时只允许失败的基础检查、导入和分析三类任务。导入重试重新接收原 ZIP，复用有界上传/校验及摘要比较，独立暂存和快照；不延长未过滤归档保留期限。分析保持原请求和快照，物理完整性仍在 Worker 校验。M3 前端补充显式重试表单；M4/M5 增加讲解和实验重试，v0.2 增加原双侧绑定的对比重试。当前六类任务的输入、确认及隔离要求见 API 清单 4.11、4.3.1、4.13 和 4.15，不能沿用旧阶段的三类范围判断当前能力。

三类任务共用投递失败处理：只将仍排队的任务终结为 QUEUE_UNAVAILABLE，不覆盖已领取/完成的状态。进程在事务提交后、投递前退出的间隙由排队期限覆盖；没有引入自动重新发布或 outbox。独立核对不依赖 Redis/Worker，数据库恢复后继续收敛。投递异常后的 API 返回 503/Location，客户端查询而不是自动换键。

基础检查、导入、分析在发布前核对状态/领取标识/期限，并在结果写入后再次核对期限；过期整体回滚。文件发布与数据库仍不是单一事务，导入保留原有扫描补偿。默认期限与配置保持 4.5，不声称恰好一次投递。Worker 边界只保留安全诊断，数据库异常不能暴露原始连接错误。

## 7. 模型接入与外发确认

- 模型用户配置仅含基础地址、模型标识和凭据，由本地服务端管理；浏览器不接收凭据，也不能提交任意模型目标 URL。不设模型预算或请求总期限，费用和供应商限制由用户判断。
- 首版使用 Chat Completions 的基础消息输入与非流式文本输出，不依赖工具调用、厂商特有结构化输出或 Agent 自动执行。基础协议参考不代表其他厂商天然兼容。[Chat Completions 参考](https://developers.openai.com/api/reference/resources/chat)
- 不携带源码进行隐式健康检查。配置兼容检查使用固定无敏感样例，仍须明确真实请求可能产生费用。
- 按已选接口及有界相关图选取必要片段，保留完整来源和选中片段，不按模型字节预算遗漏。用户可自行排除片段并重新预览，不能在确认后添加片段或更换目标。
- 外发确认绑定当前快照、片段清单及内容摘要、服务目标、模型和提示模板版本；固定模板也可查看。执行前重新校验绑定内容，变化则拒绝并重新确认。
- 不向模型发送数据库凭据、原始环境文件或未展示的其他项目内容。代码、注释和说明文档作为数据处理，不作为工具指令。
- 适配层统一处理连接失败、超时、无效结构、拒答和空内容。输出经过应用校验后才形成可用讲解；部分或非法返回不能包装为完整答案。
- 不自动重发潜在计费请求。超时只表示工作台未取得有效响应，不声称供应商已停止处理；显式重试提示可能再次计费。
- 保存讲解所用快照、证据、模型标识及模板版本；用量未知时标为未知，不编造 Token 数或金额。应用日志不记录请求/响应正文。

引用存在与行号合法只能验证机械一致性；结论是否被代码支持仍需要代表性样例的人工检查。未验证的内容在界面保持相应标记。

## 8. 内置实验与部署边界

示例应用使用独立 Compose 服务和独立数据范围，工作台通过固定服务配置调用白名单实验接口。实验不挂载导入项目或宿主 Docker socket，不接受任意镜像、脚本或目标地址。

按实验运行标识隔离创建的数据，重复请求使用该标识保护写入；观测内容包含实际输入、响应与对应写入变化。失败保留已获得的观测，清理仅作用于本次运行的示例数据，清理失败明确记录。

后端、Worker、数据库、Redis 和实验服务统一在 Linux 容器验证。宿主发布端口按本地访问规则绑定回环地址，内部服务只在必要网络互通。模型网络访问只对需要的 Worker 开放；不把普通容器描述为任意不可信代码的安全执行平台。

M5 实现：工作台 labs 只接收固定实验版本和四种预测，依据既有分析及内置九文件摘要判断适用性。公开创建、运行记录、失败重试沿用 jobs；每次保存检查点和终态前核对 claim_id/期限，过期执行不能覆盖历史。

每次 HTTP 动作在隔离 Python 子进程中访问固定 `task-board-api:8000`，最小环境、不使用代理/重定向；套接字期限 2 秒、子进程总期限 6 秒、响应正文上限 16 KiB。stdout 校验总上限 32 KiB，stderr 不回传。没有外部包、shell、任意地址或导入项目代码执行。传输失败不自动重发写操作；整个实验沿用后台任务总期限。

示例实验配置使用独立数据库/网络，复用原 TaskSerializer/create_task。运行 UUID 与固定 case 派生写入键，事务行锁串行同一运行的写入/关闭；不同运行互不清理。120 秒 TTL 及每 5 秒、每批最多 100 条的独立核对进程负责崩溃后回收。关闭标记保留，避免迟到请求重新写入；历史未确认清理不被后续核对改为已知成功。数据库或核对进程中断时必须说明清理期限受阻。

异常响应先保存已知响应，再校验预期形状和真实前后计数。清理失败即使已有四次有效观测也不能发布成功结果。单元故障注入、真实 HTTP、真实执行进程退出及独立实例停服分别记录，不混称为同一种验收。

### M3 受控前端解析与发布

解析器为 Node 24.21.0 + TypeScript 6.0.3（Apache-2.0），开发声明为 @types/node 24.19.0（MIT）。后端直接声明 jsonschema 4.26.0（MIT）；原锁文件已含该版本，本次不升级传递依赖。Node 使用内存 CompilerHost，只解析传入 JS/JSX/TS/TSX，不读取用户 tsconfig、插件、依赖或磁盘导入。相对导入只在目标唯一时解析；函数/请求包含是词法关系，直接调用和有限框架回调分别记录证据。

固定可信程序、参数数组、工作目录及精简环境；不经 shell。输入 128 MiB、源码合计 100 MiB、单文件 1 MiB、500,000 AST 节点、输出 8 MiB、Node 堆 256 MiB、60 秒进程期限。输出有界读取，超限或超时终止并回收子进程，stderr 不转发源码。CLI 成功退出 0，协议失败退出 2；异常退出、非法协议、越界引用、缺失包含关系等使任务失败。单文件语法失败保留其他结果，无前端文件返回明确空覆盖。

Python 校验 Schema、版本、快照、LF 行号、唯一标识、函数/请求引用、包含关系和覆盖计数。一次任务按 Python→Node→关联→图顺序，最后在原领取资格和事务内发布 Analysis、frontend 与 Graph。失败不留部分成功，迟到任务不能发布。HTTP GET 只校验读取，不触发解析。

关联规则仅用静态方法和完整路径。支持既有 DRF 输出中的字面路径、标准整段 Django 转换器与默认 Router lookup；不执行导入正则，不删除前缀或尾斜杠。未知基础地址、外部目标、动态配置、重复候选保留不确定性；配置或客户端别名被修改、逃逸时不当作固定值。axios 实例默认方法遵循调用参数覆盖规则；自定义传输和请求转换不确认本地目标。fetch 常量别名可识别；重复 JSX 事件或可能被后续展开属性覆盖的绑定只输出诊断。比较最多 100,000 次，候选与图沿用预算。详细版本和响应见 API 清单 4.12。


### M4 模型和教学内容实现

标准库 urllib 的单一 Chat Completions 非流式适配，无 SDK、探测、代理继承、重定向或自动重试。正式目标只允许无凭据/查询串/片段的 HTTPS 地址，密钥不写命令行、队列或日志。固定子进程通过 stdin 接收请求；请求只包含 model、messages、stream=false，无输出限额字段。HTTP 使用 timeout=None，输入与原始响应不设字节预算。父进程短周期 communicate 仅核对/续期领取，不构成总请求期限；丢失领取或异常时终止并回收子进程。

`ContextPreview` 保存精确消息与配置摘要，`ContextConsent` 与 `ExplanationRequest` 单次关联。提交在 PostgreSQL 事务/行锁内消费确认，Worker 发送前复核，完成时复用任务领取和期限约束。讲解结果与任务成功同事务写入；任何失败都保留旧有效结果。

供应商 usage 只校验三个字段为非负整数，原样记录输入、输出和总用量，不按报告用量拒绝有效结果，不估算 token 或金额。缺失 usage 保持 null。五段讲解格式、每条声明结构、引用归属和安全文本校验继续有效；拒答、截断、工具调用或非法内容不能发布。旧预算相关任务错误保持历史可读，不再由新请求生成。

Celery 进程池默认软/硬期限设为 0，讲解任务显式为 0；基础检查、导入、分析和实验通过任务注解保留原固定期限，避免进程池默认值重新限制模型等待。续期只允许仍有效且 claim_id 匹配的 running 讲解，过期不能复活。供应商默认限额、网络/系统条件仍可能终止请求，兼容性须另行真实验证。2026-09-30原预算测试成功/失败记录保留；供应商处理和费用不能由应用撤销。

教学内容经 JSON Schema 和固定题型校验后，由 `load_learning_content` 在单一事务中按版本 get_or_create；摘要不同拒绝整批覆盖。内置题绑定 9 个相关文件的 UTF-8/LF 规范化源码摘要与创建接口，记录明确维护者来源。旧版本继续可读、作答追加、提示单独记录；不运行示例业务来评分。新增两个模块各有独立初始迁移，没有改动已有业务表结构。公共请求字段上限由 4 调整到 5，匹配新历史的完整筛选与分页，仍保留原 4,096 字节请求体限制。

- M9 的有界反向遍历保留节点与边引用、路径、人工修订、候选来源和截断；人工排除不被候选开关恢复，无法映射的文件保留缺口。保持纯算法与数据库/HTTP 分离，不引入图数据库、增量缓存或运行链路采集。
- 数据迁移只增加所需记录，保留旧图和历史。真实 PostgreSQL 测试验证事务/冲突/迁移；故障注入与真实 Worker 中断分开记录，不能将 Windows 纯算法检查写成 Linux 运行验收。

### v0.3 学习与系统实验实际边界

先修图与代码关系图分开：前者发布时拒绝全部分量的环，最多 100 个节点和 400 条边；目标闭包先迭代回溯，再使用按节点标识排序的堆确定拓扑顺序。发布由现有 load_learning_content 单事务执行，知识卡片/示例版本引用必须存在，同版本摘要漂移整体拒绝。路径 GET 不变更数据库。复习只追加，原作答使用 PROTECT 外键关联且校验完整归属；旧输入摘要及 null 兼容。

固定系统实验仅支持 Linux，Popen 参数固定为可信程序及允许模式，stdin 关闭、stderr 不回传、env 为空、独立进程组。程序先设置 Linux PR_SET_PDEATHSIG 并核对父 PID，再设 CPU 1/2 秒、地址空间 128 MiB、NOFILE 32、FSIZE 0。程序不创建后代；观察方超时终止进程组并 wait。网络目标固定为 localhost:8000/task-board-api:8000，单次 TCP 0.4 秒、最多 8 个 DNS 地址、总等待 6 秒；正常进程等待 2 秒，超时场景等待 0.5 秒。现有 Worker 容器 init、内存/CPU/PID/只读文件系统限制仍必需；父进程失效的实验子进程由父死亡信号终止，init 回收孤儿。

系统实验使用独立 SystemLabRun、既有 Job 领取和检查点；真实观测逐项保存，失败保留部分结果，过期领取不再发布。新增 labs.system_run 使用现有有界非模型任务的软/硬期限；无自动重试。服务名连接不可达时明确失败，localhost 拒绝是可保存的实际观察。进程清理无法确认时不能标记 succeeded。

依据：[Python subprocess](https://docs.python.org/3.13/library/subprocess.html)、[resource](https://docs.python.org/3.13/library/resource.html)、[socket](https://docs.python.org/3.13/library/socket.html)及 [Linux PR_SET_PDEATHSIG](https://man7.org/linux/man-pages/man2/PR_SET_PDEATHSIG.2const.html)。这些限制适用于固定可信程序，不构成任意不可信代码沙箱。实际验证和平台边界仅见第三阶段计划。
