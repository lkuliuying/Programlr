## 1. 技术与职责边界

基线为 React + TypeScript + Vite + Ant Design，M3 单工作区使用浏览器 History API 管理选择，TanStack Query 管理服务端数据；尚未引入 React Router。组件与交互满足[产品需求](requirements.md)，字段及错误遵循 [API 契约规范](api-conventions.md)，方法、路径和类型归属见 [API 清单](api-catalog.md)，目录与命名见[项目结构](project-structure.md#frontend-layout)，开发顺序见[阶段计划](phase-1-plan.md)。

首版不加入 Redux、Zustand 等额外全局状态库。M1-T01 版本与验证边界见下节，实际执行结果只在阶段计划记录；当前已有基础任务页面与 M3 导入/关联工作区，讲解、学习和固定实验面板已建立。

界面定位为桌面浏览器工作台，支持窗口缩小时调整分栏或切换面板，不要求首版具备完整手机操作体验。不能因窗口变窄让关键按钮和反馈不可达。

### 1.2 参考环境及验证范围

- Windows x64：使用 `.runtime/tools` 中经过官方 SHA-256 核对的 Node 24.21.0/npm 11.19.0，保持全局安装不变。`.node-version`、`engines`、`packageManager` 和 `.npmrc` 相互核对，版本不符应失败，不静默退回全局工具。

### 1.3 声明兼容问题与受控补丁

2026-09-28 首次 Windows 与 Linux 临时容器实测：精确版本核对和 ESLint/TypeScript 负向检查通过；`npm run typecheck` 在 `strict: true`、`skipLibCheck: false` 下返回两个 TS2430：

- 锁定的 `@rc-component/image@1.10.0`：`GroupPreviewConfig.imageRender` 把父类型可缺省的 `current` 改为必填，回调参数类型不兼容。
- 锁定的 `@rc-component/picker@1.12.2`：`SinglePickerPanelProps.defaultValue` 接受 `null`，父类型不接受，接口继承不兼容。

这是实际安装的第三方声明错误，不能用 peer 范围合法或 Vite 构建通过代替严格类型检查。首次调查时官方 registry 的 Ant Design 最新版为 6.6.5、image 最新版为 1.10.0；picker 最新版 1.15.0 超出 Ant Design 的 `~1.12.2` 约束，并且不能解决 image 的错误。首次验收因此受阻，失败历史保留在阶段计划。

用户随后明确选择最小类型补丁。`tooling/type-patches.json` 记录两个包的精确版本、修改理由、四个声明文件及修改前后 SHA-256：image 的父类型改为 `Omit<InternalPreviewConfig, 'imageRender'>`，picker 的父类型改为 `Omit<BasePickerPanelProps<DateType>, 'defaultValue'>`，保留各自已有的专用属性；同时处理 `es` 与 `lib`，不改变 JavaScript 实现。

`postinstall` 使用 Node 内置 API 应用补丁，不增加依赖。全部文件通过校验后才写入，未知版本、内容或缺失文件会失败；重复应用不重复修改，写入故障会尝试恢复并报告错误。`verify:versions` 只读核对补丁已应用，`test:tooling` 验证失败路径、两种声明分发的合法输入及错误输入。保留 `strict: true`、`skipLibCheck: false`。这是由本项目承担维护责任的临时修复，并非官方原包已通过检查；未来依赖升级须重新验证并在上游修复后移除。两个原包均为 MIT，保留随包许可证；修复仅影响开发期类型检查，不增加浏览器运行代价。

来源：[上游同类问题](https://github.com/react-component/picker/issues/764)、[image 类型源](https://github.com/react-component/image/blob/master/src/PreviewGroup.tsx)。以本项目实际诊断为验收依据，上游关闭问题的状态不代表本项目已修复。修复后两个平台的全新安装、补丁状态、严格类型检查、lint、格式、2 项组件测试、10 项工具测试及构建均通过。安装体积、耗时及完整命令统一见阶段计划。

### 1.4 M1-T02 最小应用与类型来源

新增 TanStack Query 5.104.0（MIT）用于任务列表、结果查询与前台轮询，写请求禁用自动重试。M1-T02 当时只有一个任务页面，页码保存在 URL，未预装 React Router；M3 延续原生 History API。React、Ant Design、TypeScript 及已有声明补丁版本保持不变。

生成依赖选用 `@hey-api/openapi-ts` 0.99.0（MIT），官方 peer 范围支持现有 TypeScript 6；仅启用 TypeScript 插件，不生成运行时客户端。该版本引入的 YAML 解析器存在审计告警，限定在其 `@hey-api/json-schema-ref-parser` 子树把 `js-yaml` 固定为 4.3.2（MIT）；没有改变原有依赖版本。中途尝试的 0.97.0 有另一项告警，未作为最终方案。最终 `npm audit` 与实际生成/类型检查结果见阶段计划。来源：[生成器精确元数据](https://registry.npmjs.org/@hey-api/openapi-ts/0.99.0)、[类型插件](https://heyapi.dev/docs/openapi/typescript/plugins/typescript)、[TanStack Query](https://registry.npmjs.org/@tanstack/react-query/5.104.0)、[js-yaml 修复](https://github.com/advisories/GHSA-2883-xcg3-v3hh)。

`npm run api:types` 从本地 OpenAPI 生成临时类型，再由 TypeScript printer 去除工具英文注释并确认仅含类型声明，添加中文来源注释、格式化后写入既定 `schema.d.ts`；临时目录清理，不手工复制 DTO。运行时客户端仍逐字段核对未知 JSON、状态与同源结果链接。

未知提交的幂等键保存在 sessionStorage，仅属于当前页面会话；刷新可恢复同一次操作，成功响应后清除。错误结果和任务历史持久化在 PostgreSQL。只在当前列表存在 queued/running 时每 2 秒轮询，后台标签暂停，卸载取消请求，终态停止。页面明确区分队列/执行失败和传输错误；不展示无真实处理量的百分比。

应用通过 Compose 的 Nginx 同源入口运行。`npm run build` 执行严格类型检查和 Vite 构建；本任务没有提供独立 Vite 热更新代理模式，也没有提前建立完整 Playwright 工程。实际浏览器提交、结果与刷新验证见阶段计划。

### 1.6 M1 错误与类型检查基线

两套客户端从各自生成类型引用 `Error`，运行时验证 code/message/details/request_id 以及可选字段错误的数组形状；`ApiError` 保留合法 `code`、`details`、`requestId`，示例继续提供表单 fields。HTML、网络异常和畸形错误不伪造机器码或请求标识；取消和未知提交仍保留原处理语义，写请求不自动重发。

两套 `generate-api-types.mjs --check` 重新生成到临时目录并比较，缺失或漂移非零退出且不写已有声明；`npm run api:types` 才显式更新。生成器回归测试在临时工程运行真实生成命令，验证正常、缺失、漂移和文件保留。根 `scripts/check_contracts.py` 串联接口表/Schema/类型及严格 TypeScript 检查，使用方法见 [README](../README.md)，不会安装依赖或调用远程服务。UI 与业务 DTO 的职责保持不变。

## 2. 业务模块与组件组织

拟按项目导入、分析工作区、学习、实验组织功能模块。每个模块聚合其页面、业务组件、查询 hooks、API 调用和必要类型；共享层只放真正跨功能使用的客户端和通用组件，应用主题由 `src/app/` 统一配置。依赖方向为 `app → features → shared`；跨功能流程由应用层组合，不深入导入其他 feature 的内部实现。

- 页面负责布局、路由参数和业务区域组织，不直接处理复杂请求编排。
- 业务组件负责清晰的单一交互，不兼任接口客户端或跨模块数据仓库。
- 自定义 hooks 封装可复用状态流程与副作用；不把所有页面逻辑机械搬入一个巨大 hook。
- API 模块定义资源请求和转换，统一客户端负责传输、CSRF、HTTP 错误解析与取消。
- 按职责和复用需求拆分，不以固定行数强制拆分，也不为一次性简单展示创建复杂抽象。

TypeScript 开启严格模式。领域对象和接口参数显式类型化；外部数据从未知输入进行边界验证，不使用 `as` 或 `any` 绕过可预见的不确定性。新增或实质改写的代码注释使用简体中文。

现有任务历史兼容 `analysis`：排队起即要求 snapshot_id，成功只接受分析结果同源路径，非成功不接受结果链接；显示所属快照，不向 system-checks 请求分析结果。四个分析操作生成类型已经加入；M3 已建设分析提交表单、接口目录与工作区，详情见下文。

## 3. 页面与工作区

当前工作区按职责提供 11 个独立页面，共享外壳、项目和快照信息，不在工作台重复嵌入完整业务区域：

| 区域 | 核心行为 | 必须呈现的限制 |
| --- | --- | --- |
| 工作台 | 项目准备摘要、学习入口与下一步 | 未读取或未选择的资源不冒称已准备 |
| 项目导入 | 选择项目、上传 ZIP、导入规则、快照选择 | 排除文件、资源限制、失败原因 |
| 源码阅读 | 文件树、搜索、双源码及独立分段 | 快照只读、文件身份与行号校验 |
| API 分析 | 接口目录、处理对象、前端请求来源与诊断 | 字段来自既有结果；输入和响应规则通过源码核对 |
| 静态关系图 | 关系画布、节点、边及依据 | 静态推断、候选状态、覆盖缺口和截断 |
| 快照与对比 | 时间线、基准和目标、文件与接口差异 | 明确双侧归属；缺少第二快照不能展示差异 |
| 候选影响 | 起点、相关入口、路径及人工决定 | 候选默认关闭，人工决定不进入模型证据 |
| 知识与学习 | 已发布卡片、课程版本、学习目标与先修路径 | 无接口仍可读全局卡片，路径必须核对适用性 |
| 练习与实验 | 固定题、作答回顾、请求校验与系统实验 | 先作答和预测后看结果，不推断掌握、不运行导入源码 |
| 模型讲解 | 外发预览、单次确认、讲解及引用 | 服务目标、模型、证据缺口、错误与潜在重复计费 |
| 系统与任务 | 显式基础检查、检查时间和任务历史 | 历史结果不是持续监控，未检查需明确显示 |

同一对象的数据通过稳定标识联动。讲解或实验不适用于当前项目时解释原因，不通过静默跳转让用户误以为观察了自己的项目。

## 4. 状态模型

| 状态类别 | 维护位置 | 规则 |
| --- | --- | --- |
| 项目、快照、任务、讲解、作答和实验记录 | TanStack Query | 后端是持久化来源，按资源及快照构建查询键 |
| 当前项目、快照、接口及需要分享或恢复的筛选 | URL | 校验参数，缺失资源给出明确页面状态 |
| 面板展开、尚未提交的答案、临时筛选输入 | 组件状态或局部 reducer | 保持最小范围，离开对象时按规则清理 |
| 从现有数据可算出的选中节点等值 | 派生计算 | 不再存一份容易失配的副本 |

服务端数据不复制到独立全局仓库。React 官方指出冗余或重复状态容易导致同步问题；TanStack Query 用于异步服务端数据的获取与缓存。[React 状态管理](https://react.dev/learn/managing-state)、[TanStack Query 概览](https://tanstack.com/query/latest/docs/framework/react/overview)

查询键至少包含决定结果归属的项目、快照和资源标识，题目还需区分版本。切换快照时不得保留上一快照结果作为当前结果的占位内容；可继续缓存旧数据，但不能显示为新对象。

## 5. 请求与异步副作用

- 请求使用统一客户端及模块 API，路径为同源相对地址；字段命名、分页和错误对象不在组件中重新定义。
- 通用客户端位于 `src/shared/api/client.ts`，功能请求位于 `src/features/<功能>/api/`。从 `contracts/openapi.yaml` 生成 `frontend/src/shared/api/generated/schema.d.ts`，功能模块通过明确别名引用，不手写第二份相同 DTO，也不手改生成文件。生成类型不等于运行时数据已校验；渲染前核对必要标识、任务状态、引用和内容结构。
- 查询传递取消信号，卸载或失去用途时结束订阅；服务器任务是否停止以任务 API 为准，浏览器取消不是任务取消。
- 定时轮询只在相应任务处于 `queued` 或 `running` 且页面需要结果时进行，初始间隔 2 秒；后台标签暂停，返回前台时刷新。终态或卸载后清理计时器。
- 只读 GET 在明确的网络暂时故障或可恢复 5xx 时最多自动重试一次，不重试校验、权限或不存在错误。
- 写入、模型调用和实验触发不自动重发。提交前创建并保存该操作的幂等键；结果未知时使用相同键恢复请求，用户明确开始新尝试时才生成新键。
- 防重复按钮只是体验措施，后端幂等仍是最终保障。刷新后通过持久化任务列表恢复，不依赖组件内临时对象作为唯一记录。
- 迟到结果只能写入其对应查询键，不能通过闭包或全局变量覆盖当前选中对象。
- 不在渲染阶段或无用户意图的 Effect 中触发计费调用、作答提交或实验运行；开发环境 Effect 重放不应产生业务副作用。

v0.1 不提供服务端任务取消功能，也不展示会让用户误以为已停止计费或执行的取消按钮。可以关闭结果面板，后台任务仍由服务端管理。

## 6. 统一交互状态

每个数据区域明确覆盖以下状态：

| 状态 | 界面要求 |
| --- | --- |
| 尚未选择或未开始 | 说明下一步操作 |
| 首次加载或任务排队 | 展示真实状态，不虚构百分比 |
| 正在执行 | 展示当前阶段和已有处理量，可查看任务标识 |
| 无结果 | 区分没有文件、没有支持的接口和没有匹配关系 |
| 部分结果 | 展示可用内容和未解析摘要，不用绿色成功提示掩盖缺口 |
| 失败 | 显示可理解原因、适用的恢复操作和可复制请求标识 |
| 结果存在但不适用 | 说明快照、题目版本或实验来源不匹配 |

Ant Design 表单反馈用于字段错误，页面级错误用于持续故障，通知用于短暂事件。长任务不能只靠短暂 Toast 表达状态；同一错误不在多个层重复弹出。

编辑器区域只读，按行显示源码；选择引用时保留上下文和相对路径。点击失效引用时说明原因，不跳转到最接近的其他文件来模拟成功。

## 7. 样式、可访问性与内容安全

- 主题统一维护颜色、字号、间距和圆角，优先使用 Ant Design 主题能力；公共组件保留一致行为。
- 不随意添加第二套组件库。专用图或代码展示库仅在原有能力不足时引入，并记录必要性、维护与许可证检查。
- 所有交互有可读名称，键盘能进入和离开弹窗、选择节点、提交练习；关闭弹窗后恢复合理焦点。
- 色彩之外使用图标或文字表达“已识别、推断、未解析、失败”等状态，避免仅凭红绿判断。
- 图之外保留可读的步骤或关系列表，保证复杂图不成为理解和无障碍操作的唯一入口。
- 源码始终作为文本渲染；模型 Markdown 禁止原始 HTML，链接只允许经校验的安全协议，不使用未经处理的 `dangerouslySetInnerHTML`。
- 图节点、标签和引用来自受控结构化数据，不执行模型提供的脚本、HTML 或任意图代码。
- 本地存储只可保留无敏感内容的界面偏好及必要幂等标识，不保存模型凭据、源码正文或完整模型请求。敏感内容不写浏览器日志。

## 8. 前后端协作

API 的 `snake_case` 字段在生成类型和传输边界保持一致，组件内部变量采用 TypeScript 常规命名，不做全局隐式字段转换。

当前本地入口为 `http://127.0.0.1:5173`，由 Nginx 提供静态页面并同源代理 `/api/`；配置说明见根目录 `.env.example` 和 README。独立 Vite 开发代理留待确需时建立，不应把 `vite` 默认监听当作完整应用启动。CSRF 获取和提交通过统一客户端完成，不能靠关闭服务端保护或设置宽泛 CORS 解决联调问题。

前端不接收服务端模型密钥，不自行访问供应商，也不推断数据库或 Worker 状态。服务端声明的任务状态、快照和错误代码通过 [API 契约规范](api-conventions.md)解释。

接口变更先更新对应接口表，再实现并导出 OpenAPI、生成类型和执行契约验证。同一变更更新查询键、失效规则和必要页面状态，避免字段虽然编译通过但结果归属错误。

### M3 工作区实际行为

默认入口是项目工作区；`?view=jobs` 保留原系统任务页。URL 保存 project、snapshot、analysis、endpoint、node、job 以及源码 file/start/end；非法、重复或缺失上级归属的地址明确拒绝。浏览器前进、后退和刷新恢复选择。页内项目、快照、接口和历史列表分别分页，源码按最多 200 行分段请求。

Query 键包含资源归属，读取传递 AbortSignal；切换时按资源重新挂载，没有旧结果占位。文件路径必须通过当前快照清单找到唯一文件，再核对行范围和内容响应的身份/摘要；失效引用不回退其他文件。图查询的接口视角只请求该接口上游与后端下游；全图入口保留未匹配请求。证据、候选、覆盖限制、历史缺失、加载、失败和截断分别呈现。只读源码可键盘滚动，超长面板有界滚动，390 像素布局可顺序浏览。

`useIdempotentOperation` 在发送前将 UUID 和输入 SHA-256 写入 sessionStorage，不保存 ZIP、项目源码、凭据或完整输入。未知结果恢复时必须重新提供相同输入；有任务链接优先查询，提交不自动重发。离开原组件会取消请求，迟到成功回调不能切回旧工作区。可确定的新请求拒绝清除待确认标识，恢复旧操作的失败保留标识。会话存储不可用时拒绝提交，不能降级为无幂等保护的写入。

M3 沿用 React、Ant Design 与 TanStack Query，不引入额外依赖。浏览器验收使用工具提供的真实浏览器；未给工程安装 Playwright。M3 当时未提供学习、讲解及实验；当前 M4、M5 扩展见下文。


### M4 讲解与学习工作区

M4 初始工作区组合 explanations/learning 功能，以「源码关系／讲解／练习」面板切换及宽窗右侧区域呈现；该布局属于阶段历史，当前独立页面见 M21。URL 标识 preview、explanation、attempt 必须绑定分析和接口；刷新恢复历史对象与所属模块。查询键包含快照、分析、接口和对象/内容版本，切换接口清理旧对象标识，迟到响应不切回旧选择。

预览逐项展示目标、模型、模板、片段、完整消息和实际字节数，不截断消息或片段来满足旧预算。保存确认与提交讲解为不同按钮，前者无外发；用户拒绝不提交确认或任务。浏览器仅保留确认 UUID 和未确认操作的 UUID/摘要，不存正文或模型密钥。CONSENT_STALE 等明确未受理错误可释放原操作键，未知网络结果保留原键恢复；所有 POST 禁止自动重发。

页面说明应用不设置模型输出上限、请求总期限或消息字节预算，费用和供应商默认限制由用户判断。结果分别显示报告的输入、输出和总用量，缺失显示未知，不估算费用。历史预览保留原预算字段并标明已失效，禁止保存确认或提交，须准备新预览；历史失败与旧讲解仍可读。非法响应、拒答、截断及引用错误仍显示失败，不自动重新确认或重发。

讲解结构化纯文本渲染，没有 HTML、Markdown 执行、外部链接或可执行图。事实、推断、通用原理分别标明；来源沿用受控源码定位，并始终提示位置核验不等于结论正确。三类练习采用键盘可操作排序按钮、状态/记录数输入及文件/行号输入；提交前不显示答案。匹配失败仅显示无对应练习。历史绑定题目与答案版本，正确率及提示不等于掌握评估。

### M5 实验交互

labs feature 只通过生成 DTO 和同源 API 访问工作台。四种固定输入的预测必须先填写，不预填预期；保存后的预测与真实响应并列展示。页面明确示例版本、实际 HTTP 状态/正文/计数、运行失败及部分观测。响应正文只作文本显示。清理未确认有文字说明，不能以成功颜色或预设答案代替。

URL 的 run UUID 属于所选分析/接口；运行时校验同时验证快照、分析、实验 Job、运行路径及清理身份，跨上下文结果拒绝显示。切换快照/接口或开始新任务时清除旧 run，查询按所属资源构造键；刷新或从分页历史选择可恢复运行。当前任务通过 job_id 独立查询所属运行，不依赖历史当前页是否包含新记录。提交复用共享幂等 hook，取消只影响客户端等待，未知结果保留键；LAB_VERSION_MISMATCH/LAB_NOT_APPLICABLE 是确定性拒绝，释放键允许修正后新提交。失败重试沿用任务组件，创建新尝试，不覆盖旧运行。

验收包括必填预测、错误预测原样保存、响应独立显示、确定性冲突后重新提交、失败无观测/清理未知、刷新恢复、键盘和窄窗口。测试定位按钮时允许 Ant Design 的加载图标附加可访问名称，但继续断言实际提交次数和不同尝试的操作键。

- 旧讲解引用点击后打开原快照；目标适用性单独展示，并逐项说明未变、需复核、已删除或无法判断。不能跳转到新文件的相同行号来模拟证据仍有效。
- 影响结果分两侧展示起点、相关接口/入口和依据路径；候选默认关闭，开启后单独标注候选导致的范围，人工排除仍生效。覆盖缺口、截断和无结果不能用统一成功提示掩盖。

- M7/M8/M9 分别加入用户行为测试；M10 验证旧链接、刷新、前进后退、键盘、窄窗口和真实后端。新 API 只有实现并导出后才生成类型，不手写一份相同 DTO 或提前展示可用按钮。

LearningPathPanel 读取明确课程版本和目标，仅有唯一课程时默认选择；多个版本由用户选择。路径展示真实先修边及卡片，不把自评作为跳过先修的依据。AttemptReviewPanel 追加自我判断，与正确性及提示使用并列；未知请求只保存键/摘要，用户重新输入相同笔记才恢复，不把笔记正文放入 sessionStorage。重新练习使用独立表单，清空提示状态并关联原作答，原记录继续可读。

SystemLabPanel 仅接收固定两场景预测，全部选择后才能执行；不预填答案。展示实际 DNS/TCP、PID、输出、返回码、超时和回收；预测与实际不同仍原样展示。新系统历史与旧请求校验实验历史分别读取，失败/部分观测/清理未确认明确呈现。运行详情校验工作区、Job 与定义版本归属，成功响应必须完整且已回收。

URL 的 curriculum/goal/system_run 与受限 panel 选择支持刷新及前进后退，旧链接按原资源规则推断面板，切换接口清理旧实验运行；未知提交沿用原幂等 hook，409 归属错误允许用户修正。加载中按钮保持稳定可访问名称；文本内容使用 React 转义。API 复用生成 DTO 并对图环/闭包/先修顺序、课程和实验归属进行运行时校验，不引入新依赖或状态库。实际交互验收只见第三阶段计划。

### M21 统一工作台、双主题与源码窗口

`ThemeProvider` 位于 app 根层且包裹错误恢复页，使用 Ant Design 算法与 `global.css` 同一语义配色。`public/theme-init.js` 是入口 head 提前加载的同源外部脚本；只接受主题偏好，禁止改为内联脚本或放宽 `script-src`。无记录/非法值/读取异常默认深色；写入失败保留本次切换。主题只改变样式，不以主题值重建业务组件。

`WorkspaceShell` 提供品牌、当前快照路径筛选、手动主题与功能导航，不包含侧栏宣传。`WorkspaceModulePages` 定义 11 个独立页面的标题、布局容器与缺少资源引导，`WorkspacePage` 通过 feature 公开入口组合各页，并共享经过校验的项目、快照和文件元数据；服务端状态仍归 TanStack Query。工作台仅含准备摘要和跳转入口，不重复挂载源码、接口、图或学习表单；各页不再显示全局项目横幅。关系页保留屏幕阅读器标题，视觉主体直接为画布。

原生下拉选择框宽度为所在区域的 20%，保持字号、控件高度、标签和键盘操作。`SnapshotNameForm` 在导入/快照模块共享一个按快照键隔离的实例，默认折叠，显式保存服务端名称；草稿切页或关闭不丢失，不自动 PATCH。保存成功先取消详情及项目全部快照分页的在途读取，再同步缓存，避免旧响应覆盖新名称。`snapshotDisplayName` 使用真实名称或未命名状态和时间，显示名不参与 UUID 归属或排序；时间线名称、时间和计数分行，长名称可换行。

主/固定源码窗口及对比两侧源码显示服务端名称，文件身份、摘要、快照归属和分段仍按 UUID 校验。名称长度按 Unicode 字符计数，与后端 1–200 字符一致；旧空名称继续可读，不把名称当作源码定位键。全图关系页点击接口节点只更新所选节点并保持全图范围，已有接口范围的跨接口清理规则继续保留。

`AnalysisBrowser` 只负责接口清单、定义与前端来源；`StaticGraphPanel` 负责图、节点和关系依据；`CandidateImpactPanel` 负责影响起点、路径和候选人工决定。全图遗漏已选节点时，仅在存在接口范围的情况下回退该接口的有界图，保留全图截断提示和唯一人工决定表单。选中图节点保持当前模块，只有所属接口变化时才清理旧讲解预览、讲解、作答、实验运行、课程目标、面板和任务标识；同快照源码位置继续保留。API 的接口选择清理相应接口记录，分析或快照选择不继承旧上下文。

`KnowledgePanel` 独立组织卡片与 `LearningPathPanel`，不加载题目、作答或自评；无接口时只读取全局卡片并引导到 API 分析。`LearningPanel` 只负责固定题、作答反馈、历史、重新练习和 `AttemptReviewPanel`，不再包含知识卡片或课程路径。应用层在练习页组合它与 `LabPanel`，局部页签切换固定练习及受控实验，learning 不直接依赖 labs。

各业务表单仅保留一个实例并以 `hidden` 切换，按项目/快照/分析/接口键隔离对象；同一上下文内切模块、局部页签或主题保留作答、自评笔记与实验预测，不自动提交。`JobsPage` 使用 active 标识控制列表、结果查询与轮询，未激活时停用；基础检查摘要仅查询显式历史，不增加持续监控。

`section` 显式选择优先；`?view=jobs` 及资源链接继续兼容。无 section 时，旧 `panel=learning` 有作答或没有课程/目标则进入练习页，有课程/目标且无作答则进入知识页；独立 `attempt/run/system_run` 进入练习页，`curriculum/goal` 进入知识页。源码引用、讲解和对比仍按原归属恢复，原 panel 优先规则保留。浏览器 History API 管理刷新和前进/后退，不放宽参数或资源归属校验。

`SourceWorkspace` 从已校验文件清单建立目录，支持折叠及路径筛选。两个 `SourceViewer` 各自读取≤200 行；工作台翻页将各自位置写入主引用或 `file2/start2/end2`，后退/刷新可恢复。第二窗口需用户手动固定；跨快照、缺失/重复文件、无效行号、响应身份及摘要不符均明确拒绝。`source-highlight.tsx` 只按行标记 Python/TS/TSX 常见词、字符串和注释，保留文本；不承诺多行语法解析，不使用 HTML 注入。

`GraphDiagram` 使用原生 SVG 连线与可聚焦节点及关系标签，按前端/接口视图/序列化器模型分组；完整模式所有返回边均可独立选择，即使端点相同也有不同路径和标签。选中节点或关系在同一个可关闭图内依据区查看来源，不重复侧栏列表。`StaticGraphPanel` 只读取图，不额外查询分析摘要或诊断；范围、版本、候选、人工确认/排除和截断在画布内表达，诊断仍可在 API 页阅读。当前静态关系页使用完整返回图，仍遵守 100 节点/200 边既有预算。compact 模式保留≤12 节点/24 边、选中节点优先规则和紧凑列表，当前工作台不挂载该总览。快照显示服务端名称与实际日期；`SystemStatusSummary` 只查已加载最近 20 项任务范围内的显式基础检查，缺少结果显示未检查，不能宣称持续监控。模型名称使用已保存预览/讲解。

语义变量维护深浅模式的画布、面板、边框、文字、状态及源码着色。本地 SVG 与系统中文/Consolas 字体无需外部资源。断点为 1600/1200/768；独立源码页在宽度至少 1200px 时显示文件树和两个源码窗口，更窄窗口使用主/固定页签及文件树抽屉，手机功能导航使用抽屉；代码和图允许局部滚动。抽屉可用 Escape 关闭并恢复按钮焦点，提供跳到内容和 Ctrl/Meta+K 路径筛选。减少动画偏好关闭过渡。

实际任务、截图及检查命令唯一记录于[第四阶段计划 M21](phase-4-plan.md#ui-redesign)。[模块设计预览](previews/module-pages/index.html)为生成图片，仅用于设计方向，不作为实际页面或运行证据；页面字段和操作仅来自既有 API 与业务实现，不增加模型调用方式、任意运行或真人试用结论。
